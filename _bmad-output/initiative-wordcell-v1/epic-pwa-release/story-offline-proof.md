# Offline proof

## Description

Adds CAP-4's offline proof (brief §6.8) to `dist-test/` (`pwa`) and `dist/` (`dist-smoke`).

- **Order.** SPEC CAP-4's order (move, precache complete, offline reload, restore, deal, validate) governs; AD-17 Projects' and brief §6.8's "deal, validate, reload offline" wording is the known gap entry 11 (CAP-9) syncs, already recorded in SPEC CAP-4/CAP-9; SPEC wins (AGENTS.md Policy), so the build does not stop for it.
- **Start and known deal.** `seedStorage` with `fixtures/session-idle-fresh.json` (seed 1, AD-17 Seeding). A page init script (`page.addInitScript`; it runs on every navigation, so it is present on the reloaded page that deals), in both builds, passes every `crypto.getRandomValues` call through until the test arms it (a window flag set with `page.evaluate`, typed in `e2e/globals.d.ts` if needed) just before pressing the confirm's `New game`; the next one-element `Uint32Array` call writes 1 into that array, returns it and disarms; unarmed calls go to the original bound to `crypto`. After the deal assertion the test reads the consumption counter: exactly 1. It pins only the New game seed (`src/shell/seed.ts`, R-74); nav's AD-13 launch ids stay random. An init-script stub of a browser API like ticket 7.5's, test-only, no production path (SPEC Constraints).
- **Steps (both builds).** Each offline test calls `test.setTimeout(60_000)` (Playwright's default is 30 s), as `update.spec.ts` sets its own (`TEST_TIMEOUT_MS`), and attaches a `pageerror` collector before the first `goto`, asserted empty at the end, as `e2e/pwa/test-hook.spec.ts` does (console not checked: offline network errors log there). Online, compose TAN as `session-composing.json` records it: move column 3's 2-card tail (T A) onto column 6 (N) by tap-select then tap-drop (`select(page, 3, 5)`, `e2e/helpers/selection.ts`, then a tap on column 6's bottom card, as `e2e/tap.spec.ts` does) or a drag helper, press Flip (button name `Flip`; `drop` sets `destinationSide: 'left'`, NTA), and check `trayIds(page)` is `['42','0','28m']` before going on. Wait for the precache; on `pwa` stop polling `precacheComplete()` once it is true and never call it after `setOffline(true)` (a reloaded page's first recompute fetches `/sw.js`, which offline rejects to AD-15; build-notes Offline). Read the before-state, `context.setOffline(true)`, arm `page.waitForResponse((r) => isList(r.request()))`, then `page.reload()`; assert the Response `reload()` returns and the list response both came from the worker (`fromServiceWorker()`), then the restore assertion, then on `pwa` `waitForDictionary(page, 'ready')`, then `expectNoPrompt(page)` (entry 3's check, once settled, as `expectNoPrompt` requires; before the deal). Deal through Menu → New game → the confirm's `New game` button (`ConfirmDialogs.svelte`), asserting the confirm appeared (it opens only while `GameView.inProgress`), then wait until it and the Menu sheet are gone (`toHaveCount(0)`, as `e2e/confirm.spec.ts` does) and `glidesSettled(page)` (`e2e/helpers/board.ts`) before the deal assertions and the second compose. Assert the deal: `trayIds(page)` is `[]` (cards 42 and 0 back in columns); the session (`current().session` on `pwa`, stored `wordcell:session` on `dist-smoke`) has `seed: 1`, `moves: []` and cursor `{ index: 0, phase: 'idle' }`. Repeat the TAN compose and press Validate; validated means accepted: `primary-action` reads `Confirm`. No fatal surface: then `expectNoPrompt(page)` again (it rejects the AD-15 Halted `alertdialog`), and on `dist-test/` `current().kind` is `active`.
- **Restore assertion.** `pwa` (AD-17 Reading state's restore rule in full, as `e2e/restore.spec.ts` does): `seedStorage(…, { captureBoot: true })`; the before-state is a `snapshot()` (`e2e/helpers/restore.ts`); after the offline reload and `booted(page)`, the three `loaded()` fields deep-equal `JSON.parse` of the `window.__wordcellBoot` values (`null` for absent), and `loaded().session` equals `sessionOf(before)` in every field except `activeMs`, which is not smaller (the AD-9 pagehide flush accrues it), and its history/prefs clauses, as `e2e/restore.spec.ts` asserts them. `dist-smoke`: the stored `wordcell:session` read before going offline vs after the reload (read once `primary-action` reads `Validate`), every field equal except `activeMs`, which is not smaller, plus `trayIds(page)` equal before and after (`['42','0','28m']`).
- **`pwa` case.** `e2e/pwa/offline.spec.ts` (runs under `pwa` only: `dist-smoke`'s `testMatch` omits it, no config change), with a file-level `test.use({ serviceWorkers: 'allow' })` and an F6 comment, as `update.spec.ts` does.
- **`dist-smoke` case.** In `e2e/pwa/dist-smoke.spec.ts` the existing file-level tests stay unchanged; a new `test.describe('F6 serviceWorkers allow', …)` sets `test.use({ serviceWorkers: 'allow' })` with an F6 comment (never file level), and entry 7 adds its cases inside it. Same steps minus the hook reads (build-notes Offline). The precache wait polls from the spec, not the hook: read `readPrecacheManifest(request)` URLs while online, then poll until `precacheMissing(page, urls)` (`e2e/helpers/precache.ts`, built by ticket 7.4 for this poll) is `[]` and `(await navigator.serviceWorker.getRegistration())?.active?.state === 'activated'`, with the 15 s timeout of the `precacheComplete()` poll in `e2e/pwa/test-hook.spec.ts`. Setup (stub, seeding, precache poll) stays inside the offline test, never a describe-level hook (entry 7's cases share the describe; `seedStorage` throws on a second call per page). `primary-action` reading `Validate` (the restored draft with the list ready) stands in for `dictionaryState()` `ready` before the deal, the accepted Validate after it; `expectNoPrompt` runs once it reads `Validate`.
- The existing `precache.spec.ts` one-download check stays green.
- **Tests:** AD-16 AD-17 offline row of rule-coverage.md (P7, P7 `dist-smoke`); AD-8 one download (P7, existing); AD-16 no prompt row's offline part (P7: right after the offline reload, before the deal). The row's D (G2) is the device row, not this ticket's. **Owns:** the offline proof and the `allow` describe in `dist-smoke.spec.ts`. **Consumers:** entry 7 (adds its cases beside it).

## Acceptance Criteria

Verify: `npm run test:e2e:pwa` and `npm run build && npm run test:e2e:dist` pass the tests named `AD-16 AD-17 offline after the precache is complete …` on `dist-test/` and `dist/`, and `precache.spec.ts` (AD-8, dictionary once with revision `null`) passes; `npm run test:all` is green. A failure caused by production code stops the build and is reported for a fix ticket; it is never worked around in the test nor fixed in `src/` here. Test-only: no `src/`, `playwright*.config.ts` or hook-key change; the code diff (the build's plan file excepted) touches only `e2e/pwa/` specs, `e2e/globals.d.ts` if the stub's window flag needs a type, and, if a shared helper is added, `e2e/helpers/` with its cases in `e2e/helpers.spec.ts`.
