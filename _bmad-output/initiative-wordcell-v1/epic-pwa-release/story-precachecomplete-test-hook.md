# precacheComplete() test hook

## Description

Adds CAP-2's sixth hook key `precacheComplete()` (AD-17 Reading state, synchronous `boolean`) in `src/shell/test-hook.ts`, never in `sw.ts` or the worker-state module (entry 1's files). `precacheUrls` and `recomputePrecacheComplete` are the AD-17 hook module's own functions, used by its env-gated block and tree-shaken from `dist/` (proved by the `dist-smoke` check below), not a test-only path (SPEC Constraints).

- Accessor: the value starts `false`; each call starts `void recomputePrecacheComplete()` and returns the last written value. Recomputes run only when the accessor is called (never at boot or on activation); recomputes are numbered in start order and a result writes only if its number is higher than the last written one (older results are dropped).
- Recompute: a named exported async function of the hook module, e.g. `recomputePrecacheComplete(): Promise<boolean>`; in `src/` called only, with `void`, from the env-gated block; tests call it directly. It writes the value per the accessor's write rule, then resolves with the stored value (a dropped older result resolves to the newer stored value), and rejects on failure. Every recompute checks the registration first. No `navigator.serviceWorker` (F5) or no `getRegistration()` active worker in state `activated` (e.g. `activating`) gives `false` without fetching (CAP-2). The URL list is one shared promise, created by the first recompute that sees an activated worker (it fetches and parses `new URL('/sw.js', location.href)`, which is also the resolution base; Vitest stubs `location`) and reused by every later one: at most one `/sw.js` fetch per page load, made by that first recompute; after it, recomputes make no network request. The value is `true` only when the active worker is `activated` and every parsed URL, resolved against the absolute `/sw.js` URL (`new URL(url, <sw.js URL>).href`), equals the `href` of some request key's URL after `URL.searchParams.delete('__WB_REVISION__')`, in any cache whose name starts with `workbox-precache` (union; the prefix holds while `vite.config.ts` sets no `cacheId`); otherwise `false`. The check deliberately ignores revisions; callers reach `true` before any build swap.
- Parse: an exported pure function of the hook module, e.g. `precacheUrls(source: string): string[]`, throws unless the source holds exactly one `precacheAndRoute(` occurrence followed (whitespace allowed) by `[`, the array closes (a string-aware bracket-depth scan from that `[`, as `arraySlice` in `e2e/helpers/precache.ts` does; no close throws), the slice holds at least one `url:"…"` string, and its count of `url:` keys equals its count of `url:"…"` matches (a single-quoted or escaped entry throws); it extracts every `url:"…"` string of that slice by regex, never a hand list. `readPrecacheManifest`'s Node `vm` path is not importable in the page; the plan may add a page-side check (e.g. `precacheCached(page, urls)`) to `e2e/helpers/precache.ts`, with its case in `e2e/helpers.spec.ts`, for entry 6's `dist-smoke` poll to reuse.
- Failures (rule 6): every recompute failure (a rejected `getRegistration()`, a rejected `/sw.js` fetch, a non-OK response (throw with the status, as `readPrecacheManifest` does), a parse throw, a Cache Storage rejection) rejects the recompute, leaves the value unchanged, is never caught and reaches AD-15 through `main.ts`'s `unhandledrejection` handler; no catch turns it into `false`. A rejected shared URL promise is kept, never retried. There is no online check: callers reach `true` before going offline and never call it after an offline reload (the list lives per page load; an offline first fetch rejects to AD-15, build-notes Offline).
- Change together, to exactly six keys (`celebration`, `current`, `dictionaryState`, `loaded`, `precacheComplete`, `swState`): `src/shell/test-hook.ts`, `src/shell/test-hook.test.ts` (its exact sorted key list), `e2e/globals.d.ts`, `e2e/test-hook.spec.ts`, `e2e/pwa/test-hook.spec.ts`.
- F1: nothing pulls `workbox-window` into the main chunk; `e2e/pwa/build-output.spec.ts` (worker registered only from the `sw.ts` chunk) and the dev test's no-`workbox-window`-request assertion stay green; `dist/` still has no `__wordcell`.
- Interface: `window.__wordcell.precacheComplete(): boolean`, polled; the hook module's `precacheUrls` and `recomputePrecacheComplete`; the six-key frozen hook and its `e2e/globals.d.ts` type.
- Tests: AD-17 `swState()` and `precacheComplete()` row of rule-coverage.md (P7, Playwright dev); AD-17 / AD-18 no `__wordcell` in `dist/` (P7 `dist-smoke`, existing).
- Owns: `precacheComplete()` and the six-key hook.
- Consumers: entries 5 (shares `e2e/test-hook.spec.ts`), 6 and 7 (the offline and Q-42 specs wait on it).

## Acceptance Criteria

Verify:

- On `dist-test/` a `pwa` test named AD-17 polls `precacheComplete()` with `expect.poll` (`{ timeout: 15_000 }`, as the existing `swState()` poll) to `true` once the worker is activated and the precache is cached, then asserts every `readPrecacheManifest` URL is in `caches` (same comparison rule; the shared page-side check if added); the frozen hook has exactly six keys.
- In the dev server, the existing `AD-16 AD-17 the dev server never requests src/shell/sw.ts and swState() stays unregistered` test (`e2e/test-hook.spec.ts`), renamed to end `… stays unregistered and precacheComplete() stays false`, after `dictionaryState()` polls to settled, calls `precacheComplete()` and asserts it returns `false` (not `undefined`), settles that recompute by evaluating `await navigator.serviceWorker.getRegistration()` in the page plus a macrotask, reads again and asserts `false`, asserts no `/sw.js` request was made, and `swState()` is `unregistered`.
- Shell Vitest `AD-17` covers the accessor through `window.__wordcell.precacheComplete()` on a fresh module with spied `getRegistration`, `fetch` and `caches`: importing calls none of them; the first call returns `false` and makes exactly one `getRegistration()` call; after that recompute settles (all present) the next call returns `true`. Awaiting `recomputePrecacheComplete()`, it covers: all present (fakes use absolute keys, mixing keys with `?__WB_REVISION__=…` for revisioned entries and plain keys for null-revision entries, as in `dist-test/sw.js`) → `true`; each `false` case first brings the same module instance to `true` (activated worker, all keys present), changes one condition, awaits the recompute and asserts `false`: no `navigator.serviceWorker`; no active worker (`getRegistration()` resolving `undefined`, and a registration with `active: null`); `activating`; one URL missing; a URL present only in a cache with another name; the first three also assert no fetch on a fresh module instance; overlapping calls and later calls cause exactly one `/sw.js` fetch, and after it a recompute with `fetch` stubbed to reject still recomputes from Cache Storage; an older recompute settling after a newer one does not overwrite it and resolves with the newer stored value; a rejected `getRegistration()` and a rejected Cache Storage call each first bring the same module instance to `true`, assert the recompute rejects (never resolves `false`), restore non-rejecting stubs, then read the accessor → `true` and await the recompute that read started; a rejected fetch, a non-OK `/sw.js` (status in the message) and a parse throw each run on a fresh instance, assert the rejection and that a second awaited recompute rejects too with the `fetch` count still 1 (kept promise), and never call the accessor afterwards; the `precacheUrls` parse, passing on a source excerpted from today's `dist-test/sw.js` (mixed revisioned and `null` entries, the trailing `,{}` argument), and its throws (zero calls, two calls, no URLs, an unclosed array, a `url:` key not in `url:"…"` form), asserted directly.
- `e2e/pwa/build-output.spec.ts`, the dev no-`workbox-window` assertion and the existing `dist-smoke` no-`__wordcell` check pass; a new assertion in `e2e/pwa/dist-smoke.spec.ts` (the one spec only the `dist-smoke` project runs), named with its ids (e.g. `AD-17 AD-18 …`), fails if any `dist/assets/*.js` contains `precacheAndRoute` or `__WB_REVISION__` (today only `dist/sw.js` and `dist/workbox-*.js` hold them); `npm run test:all` is green.
