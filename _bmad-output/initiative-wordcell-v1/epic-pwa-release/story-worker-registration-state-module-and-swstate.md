# Worker registration, state module and swState()

## Description

Tracer bullet for CAP-1 and CAP-2: adds the F1 worker-state shell module (no `workbox-window` import; `unregistered`, `installing`, `waiting`, `active`, `failed` with CAP-1's precedence and sticky `failed`: once set this launch it stays, set here only by F17; entry 2's sticky-`failed` Vitest case tests it), `src/shell/sw.ts` registering `/sw.js` with `workbox-window`'s `Workbox` (F2; no prompt UI, no `updateSW`, no skip-waiting message; the state recomputed from the registration's slots after `register()` resolves and on every `updatefound` (its own listener) and `statechange`, with one `statechange` listener per worker, e.g. a `WeakSet`, so a worker seen at `register()` that also fires `updatefound` is not listened to twice, build-notes), `main.ts`'s boot tail (after `dictionary.load()` settles: `halted()` return, dev skip (F3; a branch around the import and the attempt, not a `return` from `boot()`, so entry 5 appends `requestPersistence()` after it), dynamic `import()`, `halted()` return again, await the attempt; F17's catch, around only the `await import('./shell/sw')` expression (build-notes "the one specified catch"; the `halted()` check and the attempt run outside it), setting `failed` and, in hook builds, `reportError(new Error(...))`), `workbox-window` in `package.json` `dependencies` at the exact version vite-plugin-pwa resolves (`"workbox-window": "7.4.1"`, what `node_modules` resolves), `package-lock.json` updated in the same change, and `swState()` on the frozen hook (five keys; `src/shell/test-hook.ts`, `e2e/globals.d.ts`, `e2e/test-hook.spec.ts`, `e2e/pwa/test-hook.spec.ts` together); because a registering worker breaks them, it narrows only the `serviceWorker.register` marker of `e2e/pwa/build-output.spec.ts` "registers no service worker automatically" to CAP-6's first clause: that marker is exempted in, and asserted present in, the `sw.ts` chunk file (`manifest['src/shell/sw.ts'].file`), found through a shared helper reading `.vite/manifest.json`, e.g. `swChunkFile()` in `e2e/helpers/dist-test.ts`, which throws when the manifest has no `src/shell/sw.ts` key or it is not `isDynamicEntry` (rule 6; a case in `e2e/helpers.spec.ts` beside `buildRoot`'s) and which entries 5, 7 and 8 reuse; `registerSW.js` absence, the `registerSW`, `vite-plugin-pwa:` and `virtual:pwa-register` markers in every scanned file and the `sw.js` no-`clientsClaim` assertion stay; the test is renamed (e.g. `AD-16 the build has no registerSW.js and registers a worker only from the sw.ts chunk`) and the plan records the new name for entries 2 and 8; entry 8 adds the manifest content check; it also runs the F6 audit of every existing `pwa` and `dist-smoke` spec (a spec routing across a reload sets its worker mode explicitly, and every audited spec that routes asserts its handler was hit; the one routing spec today is `e2e/pwa/theme.spec.ts`, `page.route('**/assets/index-*.js')` on the first, uncontrolled `goto`, no hit assertion; F6's `precacheComplete()` remedy arrives with entry 4, so here a spec that must wait for the precache polls Cache Storage from the spec; in `dist-smoke.spec.ts` any mode is set per `test.describe` with `test.use`; no spec is set to `block`, whose stubbed native `register` resolving `undefined` makes `Workbox.register()` reject). The failure detection is entry 2's: here `sw.ts` catches nothing, the attempt resolves when `register()` resolves and a rejection propagates to the AD-15 handler (rule 6) until entry 2 turns it into `failed` and makes the attempt always resolve.

Interface: worker-state module: getter and setter (F1); `sw.ts` default export or named register function returning the attempt promise (always-resolving from entry 2); `window.__wordcell.swState()`; the narrowed build-output check; the `sw.ts` chunk helper in `e2e/helpers/dist-test.ts`. Tests (rule-coverage rows): AD-16 state rows (S); `swState()` and dev values (P7, Playwright dev); build-output no-auto-registration row (B). Owns: the worker-state module, `sw.ts`, the boot tail, the `workbox-window` dependency, `swState()`, the F6 audit and the `sw.ts` chunk helper. Consumers: entries 2–9. Plan checkpoint: yes, the build pauses after its plan.

## Acceptance Criteria

Verify: On `dist-test/` a `pwa` test named AD-16 AD-17 polls `swState()` to `active` and the frozen hook has exactly five keys; in the dev server a test named AD-16 AD-17 in `e2e/test-hook.spec.ts` asserts, after `dictionaryState()` has left `loading`, `swState()` `unregistered` and no `/src/shell/sw.ts` request made (entry 5 extends that test with the persistence calls rather than adding a second one); shell Vitest `AD-16` with a faked `Workbox` covers the state precedence (pre-existing installing, waiting, active; waiting+installing → `waiting`, installing+active → `installing`, waiting+active → `waiting`; an empty registration → `unregistered`, also the value before `register()` resolves; an update found later through the module's own `updatefound`) and `messageSkipWaiting`/`messageSW` never called; the renamed build-output test, the `swChunkFile()` case and every existing `pwa` and `dist-smoke` spec pass; `npm run test:all` is green. The F4 `halted()` returns and the F17 catch are implemented here but tested by entry 5 (halt cases) and entry 7 (chunk-404 cases); the plan lists them as deferred coverage, and entries 2 and 5 extend this ticket's tests rather than add parallel ones.
