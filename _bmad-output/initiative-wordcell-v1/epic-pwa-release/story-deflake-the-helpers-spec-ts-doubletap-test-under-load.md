# Deflake the helpers.spec.ts doubleTap test under load

## Description

Fix ticket from 7.10's sweep (row D-71, B8): the test `AD-17 doubleTap gives two touch taps whose clicks have detail 1 then 2, even 600 ms apart in real time` (`e2e/helpers.spec.ts`, identified by title, not line) failed once under full-suite load in the helper's `[1, 2]` poll (inside `doubleTap`, before the test's < 400 ms check): click details `[1, 1]`; two page events (which touchstart/touchend is unknown) were timeStamped 740.1 and 2520.2 ms (a 1780 ms gap) although the CDP stamps were 80 ms apart. `doubleTap` stamps its taps so real-time lateness does not matter (`e2e/helpers/touch.ts` comment); the test's < 400 ms page-gap check after a 600 ms real wait shows that premise (AD-17 Touch's "stamped CDP taps", the claim under test) normally holds; the build answers why, under load, the page timeStamps did not follow the CDP stamps. Related history only: D-64's mechanism (unstamped taps past Chromium's tap-count window; References history); a fix here may touch D-64's path but does not close D-64 (SPEC Non-goals A7).

Sightings: bbdd2d5's final `test:all` (item 3); 30/30 alone afterwards; 0/3 counted runs at the review pass 2 and 3 trees (2d01200, f29b440), passing both trees' final `test:all`; 7.13's build counted 0/3 and a green final `test:all` at 84df83f (7.13 plan). 7.13 changed neither helper file, so no re-baseline. Everything is recorded in this ticket's plan (`story-deflake-the-helpers-spec-ts-doubletap-test-under-load-plan.md`), citing D-71; the done 7.10 plan and its D-71 row stay unedited.

## Scope

1. Edit boundary. Editable: `e2e/helpers.spec.ts`; in `e2e/helpers/touch.ts`, `doubleTap` and code only it uses (`checkPoints` and the other exports are shared, not editable); this ticket's plan. `src/` (comments included), Playwright config files and every other spec (including `doubleTap`'s callers) are not editable.
2. Never: `test.skip`, `test.fixme` or retries. Pinned with no exception: the test's title, its 600 ms `between` (the real wait from the first tap's touchEnd dispatch to the second's touchStart), its < 400 ms page-gap check, the helper's `[1, 2]` check, `DOUBLE_TAP_GAP_MS` and the report format its self-tests pin. Here the stamp premise (page event timing follows the CDP stamps whatever the real lateness; touch.ts comment, AD-17 Touch "stamped") counts as prescribed. Any other assertion is loosened only if the recorded cause shows it asserts something AD-17 Touch does not prescribe. A proven Chromium limit on honouring stale stamps takes the Input-delivery outcome (B8 proposal recording the measured lateness threshold, plus an entry-11 AD-17 Touch spine-sync note), never a loosening. A longer timeout or a retap never fixes an input-delivery cause.
3. Evidence. The only surviving evidence is the two page timeStamps in the 7.10 plan's D-71 row (:190) and Fix tickets (:204); its Final `test:all` note (:418) gives the run context (review pass 1 tree bbdd2d5, `test:e2e`, the only failure). The AC stop rules cover counted runs and the final `test:all`; in diagnostic or injection runs other tests' failures are recorded (error, trace) and do not stop the build. 5. Cause. Cause found: a temporary, reverted test-side injection modelling the named mechanism (e.g. a real `between` longer than 600 ms, or a stale first tap: a delay between taking `first` and the first dispatch; stamps kept 80 ms apart; never load alone) reproduces details `[1, 1]`. Fix proven: the same injection, same command, passes with the fix. With both halves the fix lands even when the natural before-count is 0; without cause found a suspected cause is a recorded hypothesis; without both halves, no edit. A cause involving both the helper's stamping and Chromium's handling is input-delivery unless a test-side fix proves both halves. Outcomes:
   - Test-side cause (both halves): fixed inside items 1 and 2.
   - Input-delivery cause (Chromium/CDP: stamps not honoured when stale, or delivered late): fixed test-side (e.g. page-state waits or deterministic stamping) if both halves prove it; if not (cause found only), a B8 fix-ticket proposal as for a `src/` cause (item 2 for a stale-stamp limit), and the plan stops short of `built`.

   - Never reproduces (neither half): no failure of this test in item 4's runs or this build's `test:all`, and no injection reproducing `[1, 1]`; counts and evidence recorded; the plan reaches `built` with that reason. A later sighting after a close gets a new B8 fix ticket citing this one.
