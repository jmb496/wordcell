5. Cause. Each distinct failing step or error of this test seen during the ticket is its own mode needing its own proof, else it takes the no-cause outcome; a cause proven for one mode does not claim the other sightings. Cause found: a temporary, reverted test-side injection modelling the named mechanism (e.g. a delay before the tap, or CPU throttling; never suppressing the input) reproduces the mode. Fix proven: the same injection, same command, passes with the fix. A deterministic injection fails 5/5 without the fix and 0/5 with it (`--repeat-each=5`); a probabilistic one needs ≥1 failure in the mode in 20 without and 0/20 with; all results recorded (7.10 plan D-70 precedent).
