5. Cause. Each distinct failing step or error of an R-73 test seen in an uninjected run is its own mode needing its own proof, else that mode takes the no-cause outcome (proven fixes for other modes still land); a cause proven for one mode does not claim the other sightings. Cause found: a temporary, reverted test-side injection modelling the named mechanism (e.g. a delay before the tap; never suppressing the input) reproduces the mode. Fix proven: the same injection, same command, passes with the fix. A deterministic injection fails 5/5 without the fix and 0/5 with it (`--repeat-each=5`); a probabilistic one needs ≥5 failures in the mode in 20 without and 0/20 with; "0/N with" means no failure of any kind, and an injection failure outside the modelled mode is recorded and opens no mode; all results recorded (7.10 plan D-70 precedent). With both halves the fix lands even when the natural before-count is 0; without cause found a suspected cause is a recorded hypothesis, with no test edit. A `src/` behaviour no ref prescribes, reachable by a real player's input (e.g. a tap at human speed soon after a drag being ignored), is a `src/` cause even if a test wait would hide it; input timed into a prescribed window (e.g. the AD-12 click swallow), onto a still-disabled control or into a running glide is test-side; a cause existing only through CDP/Playwright input timing (`tapAt`'s `page.touchscreen.tap` stamps dispatch time, `e2e/helpers/touch.ts` comment) is input-delivery; a longer poll or expect timeout never fixes an input-delivery cause. Outcomes:
   - Test-side cause (both halves): fixed inside items 1 and 2.
   - Input-delivery cause (Chromium/CDP delivering input late under load, as D-71; both halves): fixed test-side by page-state waits or deterministic event timestamps (the `doubleTap` precedent). If those cannot fix it (cause found only): a B8 fix-ticket proposal as for a `src/` cause, or a note for 7.14 when it is D-71's mechanism, and the plan stops short of `built`.
   - `src/` cause (cause found only; the fix proof goes with its fix ticket): no `src/` edit; the cause, its proof and a B8 fix-ticket proposal (title, finding, files, reproduction; 7.10 plan Fix tickets format) are recorded for the owner or orchestrator to add (SPEC CAP-8 technical default; ticket 7.10 Scope item 2 precedent), and the plan stops short of `built`; the owner is asked only if the fix would change what the player sees or does.
   - Reproduces, or only a load injection (e.g. CPU throttling) shows the mode, but no cause is found (neither half): counts, failing step, error and evidence recorded, no speculative edit; the plan stops short of `built` for the orchestrator.
   - Never reproduces (neither half): no failure of this test in item 4's runs or any `test:all` and no injection showing the mode; counts and evidence recorded; the plan reaches `built` with that reason. A later sighting gets a new fix ticket under B8 citing this one.
