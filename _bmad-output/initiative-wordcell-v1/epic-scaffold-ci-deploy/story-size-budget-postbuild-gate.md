# Size budget postbuild gate

## Description

Adds scripts/size-budget.mjs as postbuild: gzip-9 sum of the AD-18 counted set from dist/.vite/manifest.json against 600,000 bytes, failing on a missing font or dictionary, plus a 4,000,000-byte per-file limit on precache-glob files.

## Acceptance Criteria

Verify: npm run build prints the per-file table and passes on the tree, a forced over-budget build fails (shown in the plan, reverted), `AD-18 …` tests in scripts/size-budget.test.mjs cover over-budget, missing font, missing dictionary, counted file absent from dist (throw), the traversal, the sw.ts chunk exclusion and the CLI, and `AD-16 …` tests cover the 4 MB limit and the globPatterns and `maximumFileSizeToCacheInBytes` literals; the plan records Vitest's reported Duration from a warm `npm run test` (dictionary up to date) still under 5 s (SPEC Constraints, AD-17) after the CLI tests, plus a watch re-run after editing `scripts/size-budget.test.mjs` under 1 s (AD-17; with polling on drvfs, as ticket 1.2 measured); either over fails the ticket (temp dist fixtures stay a few bytes each; the 4 MB cases use `computeBudget` sizes, not real files). The plan also records the inline-fixture exception to build-notes § Tests of `scripts/*.mjs`: the `vite.config.ts` literal read and the `mkdtempSync` temp dists built from inline data.
**Build precondition:** clean tree on `epic-1-scaffold`.

**Build choices:**

- Script: `// @ts-check`; exports `computeBudget` and `PRECACHE_GLOB = '**/*.{js,css,html,txt,woff2,png,svg,webmanifest}'` (the exact AD-16 string) and `PRECACHE_MAX_BYTES = 4_000_000`; `main()` guarded like `scripts/build-dictionary.mjs` (`realpathSync(process.argv[1]) === fileURLToPath(import.meta.url)`); optional dist dir argument, resolved against cwd; the default `dist` resolves against the repo root (`new URL('../dist/', import.meta.url)`). package.json gets `"postbuild": "node scripts/size-budget.mjs"`.
- `computeBudget(manifest, sizes)`: `sizes` is a `Map` from dist-relative path (POSIX, no leading `./`, matching manifest `file` values) to `{ raw, gzip }` for every file under the dist dir except `.vite/` (`gzip` is used only for counted files; the CLI may gzip every file for simplicity); returns `{ rows: [{ file, gzip }], total, errors: string[] }`, `total` = sum of `rows[].gzip`, `rows` sorted by `file` (code-unit order). Errors, one string per condition, in this order: total > 600,000 (exactly 600,000 passes), naming the total and 600000; missing font, naming `src/ui/assets/wordcell-serif.woff2`; missing dictionary, naming `generated/dictionary/en.txt`; any file matching the precache glob with raw on-disk size > 4,000,000 (exactly 4,000,000 passes, as Workbox compares), one per file, naming its dist path and raw size, sorted by dist path (code-unit order). Glob match is hand-rolled from `PRECACHE_GLOB`'s brace set: a dist-relative path matches when its extension (the text after the last `.` of the basename, case-sensitive; a basename without `.` never matches) is in the set and no segment starts with `.` (mirrors Workbox `dot: false`), at any depth including root; the checked set is a superset of the actual precache list (it includes `sw.js` and `workbox-*.js`), harmless since they are small. Throws (rule 6) when there is not exactly one `isEntry: true` key (including an empty manifest `{}`), a key walked in any closure (including X) is absent from the manifest or has no `file`, or a counted file is absent from `sizes`; every throw message names the offending key or dist path. A missing font/dictionary key is AD-18's specified failure (an `errors` entry, non-zero exit; specified handling under rule 6), not a throw; SPEC's "missing budget file ... throws" is the counted-file-absent throw.
- Counted set (AD-18; reachable-from-entry follows build-notes CAP-6 "every chunk reachable from it" as the reading of AD-18's "chunks listed"), deduped by output path (counted and listed once): the dist-relative file `index.html` (dist/index.html; the manifest key `index.html` maps to the entry JS); counted chunk keys, order-independent: C = closure from the single `isEntry: true` key over `imports` and `dynamicImports`, not following any `dynamicImports` edge to `src/shell/sw.ts`; X = closure of `src/shell/sw.ts` (when some walked key's `dynamicImports` lists it) over static `imports` only, never counted by itself; C additionally gets the full closure (imports and dynamicImports, same sw.ts-edge rule) of every `dynamicImports` target of a key in X (AD-18, build-notes CAP-6: counting lazily loaded chunks is intentionally conservative). Counted keys = C, so X keys reached from C, including sw.ts via a counted chunk's static import (it loads at first paint), are counted. Each closure keeps its own visited set (cycles end) and checks every walked key exists (so a dangling `src/shell/sw.ts` reference also throws). A path is counted when any counted key lists it, even if an uncounted key also lists it; counting each counted key's `file` and every `css` entry, but never `assets` entries apart from font and dictionary, since AD-18 counts chunks and the architecture has no worker or `?url` CSS; the font and dictionary by manifest source keys `src/ui/assets/wordcell-serif.woff2` and `generated/dictionary/en.txt`, counting each key's `file` (the dictionary key is not linked from the entry). An absent key, or a key without `file`, is the missing font / missing dictionary error. The plan's handoff records, as a spine wording bug (spec wins) and for the epic retrospective's spine update, the AD-18 "chunks listed" → "chunks in C: reachable from the entry over static and dynamic imports without following a dynamic import of `src/shell/sw.ts`, plus everything reachable from a dynamic import made by the sw.ts static-import closure" wording.
- CLI `main()`: throws with the path in the message when `<dist>/.vite/manifest.json` or `<dist>/index.html` is missing; walks the dist dir with `node:fs`, gzips each file at level 9 with `node:zlib`, calls `computeBudget`, and only when it returns prints the table to stdout (`<file> <gzip>` lines in `rows` order, then `total <n> / 600000`) before any error lines so it appears on `errors` failures, then each error to stderr (each 4 MB violation named), and exits non-zero when `errors` is non-empty via `process.exitCode = 1` (no `process.exit()`, so piped output drains); more than one argument, or an argument starting with `-`, throws a usage error (rule 6); a throw propagates uncaught (rule 6): non-zero exit, no table.
- Forced over-budget build: after a normal build, append about 300,000 bytes of base64 lines from random bytes (e.g. `crypto.randomBytes(225000).toString('base64')` split into 76-char lines) to `generated/dictionary/en.txt` (never `data/enable1.txt`), run `npm run build`, record in the plan the dictionary row above 600,000 gzip bytes, the total and the non-zero exit (if the dictionary row is not above 600,000 or the build still passes, append more and repeat), then restore with `npm run build:dictionary` (the `prebuild` staleness check does not regenerate a newer hand-edited output) and show a rebuild passes, recording the green exit and the dictionary row back to its measured value (~454 KB).

**Never:** a new npm dependency; a change to `vite.config.ts`; an edit to `data/enable1.txt`; `postbuild` on `build:test`. Do not push.

**Delta checks (delta-checks.md rows for CAP 6):**

- `postbuild`: `npm run build` prints the per-file table; `AD-18` script tests.
- SPEC CAP-6 success: `postbuild` passes on the tree (dictionary ≈ 454,262 B gzip, measured 2026-09-27; informational: the plan records the measured value, no test asserts it; a few KB variance is expected and not a finding); `scripts/size-budget.test.mjs` covers over-budget, missing font, missing dictionary, the `src/shell/sw.ts` chunk exclusion (fixture manifest; no such chunk exists until epic 7) and the 4 MB file limit.
- SPEC Success signal: a `?url` dictionary over 600,000 gzip bytes turns `npm run build` red (forced once, shown in the plan, reverted).
- Ticket 1.2 deferred guard: an absent manifest key `generated/dictionary/en.txt` gives the missing-dictionary error (in `errors`, table printed); a key whose file is absent from dist is the counted-file throw (non-zero exit, no table); both fail `npm run build` and together close ticket 1.2's deferred permanent dist-asset guard on `npm run build`/CI; the evidence is the `AD-18` CLI cases (missing key, missing file), since postbuild is the same CLI and its non-zero exit fails `npm run build`; no real-build reproduction needed; the plan records both and the guard closed.

**Tests:** in `scripts/size-budget.test.mjs`, on `computeBudget(manifest, sizes)` with inline fixtures copying the real manifest shape (dictionary key not linked from the entry); each test asserts `errors` equals exactly the expected list (length and content, by substring or `toEqual` on the chosen strings):

- `AD-18 …`: total 600,000 passes and 600,001 fails; missing font key; missing dictionary key; dictionary key present without `file` gives the missing-dictionary error; a counted file absent from `sizes` throws (fixture drops the dictionary's file); a visited chunk key without `file` throws; no `isEntry` key throws; two `isEntry` keys throw; empty manifest `{}` throws; a dangling import key throws; `index.html` (the dist file) is counted; a lazily loaded chunk with CSS is counted; a shared chunk imported by two chunks counts once (and `total` asserted); a CSS file listed by two visited chunks appears once in `rows` (and `total` asserted); a two-chunk import cycle terminates and each counts once; an unrelated image asset is not counted; one combined case: over-budget, missing font, missing dictionary and two 4 MB files given in reverse path order → `errors` `toEqual` the full ordered list; sw.ts exclusion: the entry dynamically imports `src/shell/sw.ts`, which statically imports a chunk reachable only through it (excluded) and a chunk the entry also imports (counted), both asserted, plus the `src/shell/sw.ts` key's own `file` and a css unique to it absent from `rows`, and a CSS path listed by both the sw.ts key and the entry appears once in `rows`; a sw.ts-only static import that dynamically imports a chunk → that chunk is counted; order independence: sw.ts statically imports S and dynamically imports D, D statically imports S → S is in `rows`; the entry statically imports a chunk that statically imports `src/shell/sw.ts` → sw.ts's `file`, css and static imports are in `rows`; a dangling `src/shell/sw.ts` key throws; a chunk imported only by sw.ts is dangling → throws.
- `AD-18 …` CLI: a child process runs `node scripts/size-budget.mjs <distDir>` against a tiny temporary dist fixture (manifest, `index.html`, small assets): once passing (fixture holds entry, font and dictionary keys; exit 0, stdout contains each counted fixture path (`index.html`, entry JS, entry CSS, font, dictionary) and the total line), once failing (missing dictionary key, non-zero exit, stdout still contains the total line, stderr contains the missing-dictionary error text and stdout does not); a temp dist whose manifest lists the dictionary key but whose `file` is not on disk exits non-zero, stderr names the path and stdout has no `total` line; a temp dist without `.vite/manifest.json` and one without `index.html` each exit non-zero with that path in stderr; two arguments, and `--x`, each exit non-zero with usage text on stderr and no `total` line on stdout. The 4 MB CLI error path is covered by the `computeBudget` 4 MB tests plus the missing-dictionary CLI case (the stderr path is shared); no separate 4 MB CLI case. Cases spawn with async `execFile`, run concurrently (`Promise.all` or `describe.concurrent`) to stay within the AD-17 limits. Fixtures are created once per file in `beforeAll` under `mkdtempSync(join(os.tmpdir(), 'size-budget-'))` and removed in `afterAll` with `rmSync(..., { recursive: true, force: true })`. Tests resolve the script and `vite.config.ts` from `import.meta.url` (e.g. `fileURLToPath(new URL('./size-budget.mjs', import.meta.url))`, `new URL('../vite.config.ts', import.meta.url)`), not cwd.
- `AD-16 …` (4 MB cases use an uncounted glob-matching file, e.g. `icons/x.png`, with a small gzip value so each case yields only the 4 MB error): raw 4,000,000 passes and 4,000,001 fails; a precache-glob file outside the manifest (`icons/big.png`) over 4 MB fails; a root file and a nested `icons/x.png` match the glob, a `.map` file does not, and `.well-known/x.js` over 4 MB does not match; `PRECACHE_GLOB` equals the AD-16 string, and the test builds the expected text `globPatterns: ['${PRECACHE_GLOB}']` from the imported constant and asserts the unchanged `vite.config.ts` source contains it (`vite.config.ts` imports nothing new), so the constant and the config cannot drift silently; likewise it asserts the source contains `maximumFileSizeToCacheInBytes: 4_000_000` and `PRECACHE_MAX_BYTES` equals 4,000,000.

`postbuild` runs only after `build`, not `build:test`; `test:all` does not run `build`, hence the CLI test.
