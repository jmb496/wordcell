# PWA packaging: manifest, service-worker settings, head, icons and palette

## Description

Sets vite.config.ts to AD-16 (registerType prompt, injectRegister false, A-D5 manifest, globPatterns, `maximumFileSizeToCacheInBytes: 4_000_000`, build.manifest true beside ticket 1.4's `build.assetsInlineLimit` (AD-18 Font), which stays unchanged), the index.html head, scripts/build-icons.mjs with committed SVG sources, PNGs and `public/favicon.svg`, and the DESIGN.md palette and overflow rules in src/ui/app.css and src/ui/App.svelte. Extends ticket 1.3's `e2e/pwa/precache.spec.ts`, adds `e2e/pwa/build-output.spec.ts` (reads `dist-test/` from disk as `font.spec.ts` does) and `e2e/app-shell.spec.ts` (head and style cases).

## Acceptance Criteria

Verify: `e2e/pwa/build-output.spec.ts` deep-equals the manifest, finds no `registerSW.js` and no registration code, finds `.vite/manifest.json` present, and reads the three icon sizes; `e2e/pwa/precache.spec.ts` matches the precache list to the AD-16 globPatterns; `e2e/app-shell.spec.ts` reads the head, the `--wc-*` palette and the body styles in `android` and `desktop`; `node scripts/build-icons.mjs` regenerates the three committed PNGs and `public/favicon.svg`; `npm run test:all` is green, and `npm run build && npm run test:e2e:dist` is green with the result recorded in the plan, `dist/` holding no `registerSW.js` and holding `dist/.vite/manifest.json` (the path CAP-6 reads), shown by quoting in the plan the command `test ! -e dist/registerSW.js && test -f dist/.vite/manifest.json && echo PASS` and its `PASS` line after `npm run build`.

**Build precondition:** clean tree on `epic-1-scaffold`.

**Never:** worker registration code or `src/shell/sw.ts` (epic 7); a `beforeinstallprompt` listener or custom install UI (AD-16, brief §7); a postbuild or size-budget script (CAP-6, ticket 6); a `*.screens.spec.ts`; a new npm dependency; an AGENTS.md edit; `dontCacheBustURLsMatching`; `devOptions` in the VitePWA config (the worker stays disabled in `vite dev`, AD-16); a console-error allow-list or filter in `e2e/pwa/dist-smoke.spec.ts` (rule 6: a dist-smoke error the builder cannot fix at its cause is a Halt, recorded in the plan with the message text). Do not push.

- `public/icons/` generated by `node scripts/build-icons.mjs` [ASSUMPTION A-A7]: sources `scripts/icons/icon.svg` (→ `icon-192.png`, `icon-512.png`) and `scripts/icons/icon-maskable.svg` (→ `icon-512-maskable.png`); the script also writes `public/favicon.svg` (replacing the scaffold's Vite logo; owner answer 2026-09-28) as a byte-for-byte copy of the committed source `scripts/icons/favicon.svg`, a simplified `W` card on the `table` colour. The favicon source follows rules (a)–(e) below; in place of (f) it has no `<text>` or `<tspan>` and draws the `W` as shapes (a browser renders an SVG favicon as an image, which loads no web font, so text would fall back to a host font). SVG source rules (each checked by `scripts/build-icons.test.mjs` on every committed source; for (b)–(f) a property counts when set as a presentation attribute or an inline `style` declaration on the same element, `style` winning when both are present; hex compared case-insensitively): (a) root `viewBox` exactly `0 0 N N`, no root `width`/`height`; (b) the first shape element (`rect`, `circle`, `ellipse`, `path`, `polygon`, `polyline`, `line`, `text`) in document order, after XML comments are stripped, is a `<rect>` with `x` 0, `y` 0, `width` and `height` N, no `rx`/`ry`, no `transform` on it or any ancestor, and `fill` the `table` hex (the maskable icon is full-bleed); (c) every `fill`, `stroke`, `stop-color` and `color` value is `none` or a hex matching one of the six token values listed below, written literally (an SVG cannot read the `--wc-*` variables); any other colour syntax fails; (d) every shape element and `tspan` carries an explicit `fill` on itself, so nothing paints SVG's default black; (e) elements only from `svg`, `g`, `rect`, `circle`, `ellipse`, `path`, `polygon`, `polyline`, `line`, `text`, `tspan`, `title`, `desc`; no `class`, `href` or `xlink:href` attribute; no `opacity`, `fill-opacity` or `stroke-opacity` below 1; (f) at least one `<text>`; every `<text>`/`<tspan>` has `font-weight` exactly `600` and a `font-family` that equals `WordCell Serif` after trimming and removing one pair of matching outer quotes, with no comma (no fallback family); each `<text>`'s trimmed text content (concatenated descendant text) equals `W` exactly (DESIGN.md App icon). The test uses a small hand-written tag tokenizer (open, close and self-closing tags, text nodes, an element stack for ancestor checks) and fails on CDATA, entity references, DOCTYPE, or processing instructions other than an optional XML declaration. The script exports `ICONS` (array of `{ source, output, size }`: `icon.svg` → `icon-192.png` 192, `icon.svg` → `icon-512.png` 512, `icon-maskable.svg` → `icon-512-maskable.png` 512; `source` and `output` are bare file names resolved against `scripts/icons/` and `public/icons/`), `FAVICON` (`{ source: 'favicon.svg', output: 'favicon.svg' }`, resolved against `scripts/icons/` and `public/`) and `readSources(sourceDir)`, which returns a `Map` from each unique source file name to its SVG text (`icon.svg` read once, `favicon.svg` included) and throws naming the first missing file in `ICONS` order then `FAVICON` (`icon.svg`, then `icon-maskable.svg`, then `favicon.svg`), and a pure `readFont(fontPath)` that returns the woff2 bytes and throws naming the path when the file is missing, and guards its CLI entry (SPEC D3). The CLI calls `readSources` and `readFont` on the committed woff2 before it loads Chromium, and loads it only via `await import('@playwright/test')` inside the render path, never a top-level import (so the Vitest test does not load Playwright). Paths (`scripts/icons/`, the woff2, `public/icons/`, `public/favicon.svg`) resolve from `import.meta.dirname`, not the cwd. It creates `public/icons/` (`mkdir` recursive; git keeps no empty directory). Chromium comes from the existing `@playwright/test` (no new dependency) and renders each at viewport = output size, `deviceScaleFactor` 1: `page.setContent` loads a wrapper page (`html, body` margin 0, width and height 100 %, overflow hidden, background `#15171B` as page hygiene only (rule (b) and its test are the guard); `svg` display block, width and height 100 %) with the inline SVG markup and an `@font-face` (`'WordCell Serif'`, 600) whose `src` is a base64 `data:` URL of the committed `src/ui/assets/wordcell-serif.woff2` (no `file://` URL). Before each screenshot it awaits `document.fonts.load('600 1em "WordCell Serif"', 'W')` and throws unless the result has exactly one face and that face's `status` is `'loaded'` (the checks of `e2e/pwa/font.spec.ts`; rule 6; `document.fonts.ready` resolves on a failed load and `document.fonts.check` is true when no face matches), so no host font is used; this in-page check is proven by the plan's run log and the gate-4 look, not by a unit test. `tsconfig.node.json` type-checks `scripts/**/*.mjs` with lib ES2023 (no DOM), so in-page code goes to `page.evaluate` / `waitForFunction` as a string; the tsconfig is not changed. Colours are DESIGN.md tokens (`table`, `card-face`, `card-edge`, `card-ink`, `accent-teal`, `accent-orange`); flat fills and strokes, no gradient or filter (DESIGN.md App icon). A missing source throws (rule 6). "Regenerates" means: run the script, `git add public/icons public/favicon.svg`, run it again, and `git diff --exit-code --stat public/icons public/favicon.svg` (working tree vs index) exits 0 with no output; the plan quotes the command and its result; the files staged by this procedure stay staged for the ticket's commit. The script header comment and the plan record the `@playwright/test` version (from its `package.json`) and the Chromium `browser.version()` the script prints when run, quoted in the plan.
