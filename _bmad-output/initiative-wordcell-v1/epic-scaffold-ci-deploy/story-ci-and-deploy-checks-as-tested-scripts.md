# CI and deploy checks as tested scripts

## Description

Closes retro A4 and A6 (R3, R6, P3). The retro actions are owner approved (tickets.toml, "owner approved 2026-09-28"), the rule-7 authorisation for this ticket; it supersedes the "no new script file" / "no new file under `scripts/`" constraints of tickets 1.8 and 1.9 (retro A6). Everything before gate 4 is built unattended.

- Scripts (SPEC D3): Node ESM, no new dependencies: `scripts/flaky-report.mjs` and `scripts/deploy-check.mjs` (verify dist, workers.dev URL extraction from the wrangler log, post-deploy checks). Each exports pure, testable functions plus a thin guarded CLI entry; each workflow step becomes one `node scripts/<name>.mjs …` call with no other inline logic; the `deploy` step's `wrangler deploy | tee` stays.
- CLIs: `node scripts/flaky-report.mjs` reads the current env names (`OUTCOME_DIST_SMOKE`, `OUTCOME_E2E`, `OUTCOME_PWA`, `PW_JSON_DIR`, `GITHUB_STEP_SUMMARY`; either of the last two unset or empty exits non-zero naming it); `node scripts/deploy-check.mjs verify` and `… post-deploy <wrangler log path>` (the step passes the `$RUNNER_TEMP` log path); any other subcommand exits non-zero. Test-only override: env `DEPLOY_CHECK_BASE_URL`, never set in either workflow, replaces the URL only after extraction from the log succeeded (the log must still contain a workers.dev URL); the CLI logs a line when it is set. `flaky-report.mjs` imports only `node:` built-ins (no npm imports: `npm ci` may not have run).
- Behaviour is ported 1:1 from ci.yml `flaky report` and deploy.yml `verify dist` and `post-deploy check` at commit 564d2c2 (tickets 1.8 and 1.9 are the behaviour spec); the only intended changes (fail fast, rule 6) are the added immutable targets, the verify-dist additions, the stricter flaky shape (string spec `file`/`title`, suite `title`) and the `/index.html` redirect cap and 3xx-without-`Location` rule, all below.
- Flaky report contract: flaky tests never fail the job (AD-18 "non-gating"); a missing report after a successful step, malformed or wrong-shape JSON, or an unexpected outcome still exits non-zero naming the step id (rule 6, as today). Shape: root an object with a `suites` array; each suite has a string `title`, and its `suites` and `specs` are arrays when present; each spec has string `file` and `title` and a `tests` array whose entries have string `status` and `projectName` (Playwright 1.63 `JSONReportTest`); the step keeps `if: ${{ !cancelled() }}`.
- HTTP: `node:http`/`node:https` (picked from the URL protocol), HEAD for the cache and status checks, GET for the index wait, no `Accept-Encoding`; `cache-control` lines (name case-insensitive) are counted from the final response's `rawHeaders` (exactly one, equal value); no redirect following except for `/index.html`, which follows to the final response (`Location` resolved against the request URL, follows at most 5 redirects; exceeding the cap or a 3xx without `Location` is a failed attempt) and only logs the first response's status and `cache-control` (as `-sIL` today; a direct 200 passes). The index wait compares the GET body byte-for-byte with `dist/index.html`.
- Test seam: attempt counts, delay, base URL, per-request timeout (wall time including body and `/index.html` redirects, like curl `--max-time`) and dist directory are parameters; production defaults unchanged (24 attempts for the index wait, 3 per check, 5 s apart, 10 s timeout, `dist/`). A timeout or connection error is a failed attempt.
- Immutable targets: the post-deploy check asserts immutable on the first `dist/assets/*.js` in code-point sorted order, logged as `asset for check 1:` (as today), exactly one `dist/assets/en-*.txt` and exactly one `dist/assets/*.woff2`, checked right after the JS check (dictionary, then woff2), each logging its asset name and an `ok:` line (gate-4 evidence); verify dist requires exactly one match per glob, naming the glob on zero or several (rule 6), and reports every failure (missing files, each glob count) before exiting non-zero, as today.
- Pre-deploy config test (R3), in `scripts/deploy-config.test.mjs`: validators are pure functions exported from `scripts/deploy-check.mjs` taking file text, run on the committed files and on inline mutated copies. `public/_headers` parses into a path → headers map (rule order ignored) and passes only when it equals AD-18's five rules exactly (`/assets/*` the immutable value; `/`, `/index.html`, `/sw.js`, `/manifest.webmanifest` `no-cache`): one `Cache-Control` per path, header names case-insensitive, values compared exactly, blank (empty after trimming) lines ignored, no extra or duplicate paths or headers. Grammar: a line starting with `/` is a path; a line indented by spaces or tabs, `Name: value` split on the first `:` and trimmed, is a header of the preceding path; any other non-blank line (including `#` comments, `!` detach lines, a header before any path) fails naming the line. `public/.assetsignore` non-blank lines are exactly `.vite`. `wrangler.jsonc` is parsed with `JSON.parse` (a comment or trailing comma fails); top-level keys exactly {`name`, `compatibility_date`, `workers_dev`, `preview_urls`, `assets`}; `name` `"wordcell"`, `workers_dev` true, `preview_urls` false, `assets` deep-equal `{ "directory": "./dist" }`; `compatibility_date` a `YYYY-MM-DD` string not later than the `DEFAULT_COMPAT_DATE` read from the pinned wrangler's `node_modules/wrangler/wrangler-dist/cli.js` (a missing constant fails; retro P3).
- Tests: `scripts/flaky-report.test.mjs`, `scripts/deploy-check.test.mjs`, `scripts/deploy-config.test.mjs` (Vitest include `scripts/**/*.test.mjs`), names starting `AD-18 …`. Network tests use an in-process `node:http` server on 127.0.0.1 port 0, zero delay, no external network, inside the AD-17 unit budget. A unit test covers both protocol → module mappings; the real https path is first exercised at gate 4. Each script gets one test spawning its CLI (`node:child_process`), `cwd` a temp dir holding `dist/` and the log (post-deploy also against the local server via `DEPLOY_CHECK_BASE_URL`), so the CLI wiring runs before gate 4 (retro P3). At least one flaky-report fixture, trimmed and inline in `scripts/flaky-report.test.mjs` (SPEC Constraints; never under root `fixtures/`, AD-17 Seeding), comes from a real `--reporter=json` test run (not `--list`) in which one test inside a nested describe passes on retry (`flaky`); a comment records the capture command and Playwright version; its test asserts the full summary text (heading and entry order).
- actionlint: a gating step in ci.yml's `test` job right after `setup-node` (before `npm ci`): `docker run --rm -v "$PWD":/repo -w /repo rhysd/actionlint:1.7.12` (1.8's tag, 1.8 plan:84), no config or flags. CI-only like screenshots (`test:all` does not run it; Docker is not a unit-gate dependency), the second CI-only exception in AD-17 Scripts / AD-18 CI. The build runs the same command locally as its proof (Docker reachable 2026-09-28).
- Carried constraints: values reach scripts only through step `env:` or arguments (no `${{ }}` inside `run:` bodies); secrets stay only in the `deploy` step env; deploy.yml keeps `npm ci`, so scripts run after checkout.
- Doc updates, each tagged "(ticket 1.11, 2026-09-28)": spine AD-18 `Binds:` (`scripts/flaky-report.mjs`, `scripts/deploy-check.mjs` and the three test files), AD-18 CI (actionlint step, script steps) and AD-18 Deploy (immutable on JS, dictionary and woff2; extended verify dist; pre-deploy config test), AD-17 Scripts (actionlint CI-only; tickets touching `.github/workflows/` run the pinned actionlint command locally); spine Scaffold deltas Docker line ("screenshot baselines and the actionlint proof"); SPEC CAP-8 and CAP-9 success, D6 (actionlint now in CI) and the Assumptions `deploy.yml` curl line (now `deploy-check.mjs post-deploy`); build-notes CAP-8 and CAP-9; delta-checks rows 48–49; epic Notes (the Docker "Unknown" is superseded). The AGENTS.md managed block is unchanged (actionlint is a lint step, not a suite).

## Acceptance Criteria

Verify: `npm run test:all` is green and the unit suite stays under 5 s; each of these fails a named `AD-18` test: `_headers` without the `/sw.js` rule, with a wrong immutable value, an extra rule, a duplicate rule, a `#` line, a `!` line or a header before any path; `.assetsignore` without `.vite` or with an extra line; `wrangler.jsonc` with an extra key (e.g. `assets.not_found_handling`), a missing key, `preview_urls: true` or a `compatibility_date` later than `DEFAULT_COMPAT_DATE`; the flaky report lists a flaky entry in the summary and as a `::warning::` with `%` escaped, handles each outcome branch (skipped, failure without file, success without file → non-zero, unexpected outcome → non-zero), exits non-zero naming the step id on malformed JSON, valid JSON without `suites` and a spec without `tests`, still lists a flaky entry when that step failed, lists all three steps as "not run" when actionlint fails, writes a flaky title containing CR/LF as one line (spaces), and writes "No flaky tests." for zero flaky; an unknown `deploy-check.mjs` subcommand exits non-zero; the deploy check fails on a wrong or duplicated `cache-control` on the woff2 and on the dictionary, a redirect before 200 on a no-cache check (not followed), `/index.html` whose final response after a 307 lacks `no-cache`, a 6th redirect (5 followed pass) or a 3xx without `Location` on `/index.html`, a 200 where 404 is expected, an index body mismatch, a server that never responds (short test timeout) and a refused connection (each a failed attempt; the check fails once attempts run out), no workers.dev URL in the log, and verify dist with zero or two `en-*.txt`, zero or two `*.woff2`, a missing required file or zero `*.js`; each CLI spawn test passes; actionlint exits 0 locally and in CI. Gate 4: the owner pushes `epic-1-scaffold` (CI green including actionlint and the flaky-report summary), then merges it to `main` and pushes (as in 1.9), and the Deploy run's post-deploy log shows every check ok, including the dictionary and woff2.
