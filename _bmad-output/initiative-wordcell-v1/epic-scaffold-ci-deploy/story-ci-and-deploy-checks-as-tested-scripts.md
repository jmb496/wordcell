# CI and deploy checks as tested scripts

## Description

Closes retro A4 and A6 (R3, R6, P3). The retro actions are owner approved (tickets.toml, "owner approved 2026-09-28"), the rule-7 authorisation for this ticket; it supersedes the "no new script file" / "no new file under `scripts/`" constraints of tickets 1.8 and 1.9 (retro A6). Everything before gate 4 is built unattended.

- Scripts (SPEC D3): Node ESM, no new dependencies: `scripts/flaky-report.mjs` and `scripts/deploy-check.mjs` (verify dist, the workers.dev URL extraction from the wrangler log, the post-deploy checks). Each exports pure, testable functions plus a thin guarded CLI entry; each workflow step becomes one `node scripts/<name>.mjs …` call. No inline logic remains in either workflow beyond those calls; the `deploy` step's `wrangler deploy | tee` stays.
- CLIs: `node scripts/flaky-report.mjs` reads the current env names (`OUTCOME_DIST_SMOKE`, `OUTCOME_E2E`, `OUTCOME_PWA`, `PW_JSON_DIR`, `GITHUB_STEP_SUMMARY`); `node scripts/deploy-check.mjs verify` and `node scripts/deploy-check.mjs post-deploy <wrangler log path>` (the step passes the `$RUNNER_TEMP` log path as an argument); any other subcommand exits non-zero. `flaky-report.mjs` imports only `node:` built-ins (no npm imports), so it runs on the runner's default Node when actionlint fails before `setup-node`.
- Behaviour is ported 1:1 from ci.yml `flaky report` and deploy.yml `verify dist` and `post-deploy check` at commit 564d2c2 (tickets 1.8 and 1.9 are the behaviour spec); the only intended changes are the added immutable targets and the verify-dist additions below.
- Flaky report contract: flaky tests never fail the job (AD-18 "non-gating"); a missing report after a successful step, malformed or wrong-shape JSON, or an unexpected outcome still exits non-zero naming the step id (rule 6, as today). Shape: root an object with a `suites` array; each suite's `suites` and `specs` are arrays when present; each spec has a `tests` array whose entries have string `status` and `projectName` (Playwright 1.63 `JSONReportTest`); the step keeps `if: ${{ !cancelled() }}`.
- HTTP: `node:http`/`node:https` (picked from the URL protocol), HEAD for the cache and status checks, GET for the index wait, no `Accept-Encoding`; `cache-control` lines are counted from the final response's `rawHeaders` (exactly one, equal value); no redirect following except for `/index.html`, which follows to the final response (`Location` resolved against the request URL, at most 5 hops; exceeding the cap or a 3xx without `Location` is a failed attempt) and only logs the first response's status and `cache-control` (as `-sIL` today; a direct 200 passes). The index wait compares the GET body byte-for-byte with `dist/index.html`.
- Test seam: attempt counts, delay, base URL, per-request timeout (total wall time per request including the body and any `/index.html` redirects, like curl `--max-time`) and dist directory are parameters; production defaults unchanged (24 attempts for the index wait, 3 per check, 5 s apart, 10 s timeout, `dist/`). A timeout or connection error is a failed attempt.
- Immutable targets: the post-deploy check asserts immutable on the first `dist/assets/*.js` in code-point sorted order, logged as `asset for check 1:` (as today), exactly one `dist/assets/en-*.txt` and exactly one `dist/assets/*.woff2`; verify dist requires exactly one match for each of those two globs and fails naming the glob on zero or several (rule 6).
- Pre-deploy config test (R3), in `scripts/deploy-config.test.mjs`: `public/_headers` parses into path → headers and passes only when it equals AD-18's five rules exactly (`/assets/*` the immutable value; `/`, `/index.html`, `/sw.js`, `/manifest.webmanifest` `no-cache`): one `Cache-Control` per path, header names case-insensitive, values compared exactly, blank lines ignored, no extra or duplicate paths or headers. Grammar: a line starting with `/` is a path; an indented `Name: value` line is a header of the preceding path; any other non-blank line (including `#` comments, `!` detach lines, a header before any path) fails the test naming the line. `public/.assetsignore` non-blank lines are exactly `.vite`. `wrangler.jsonc` is parsed with `JSON.parse` (a comment or trailing comma fails the test); top-level keys exactly {`name`, `compatibility_date`, `workers_dev`, `preview_urls`, `assets`}; `name` `"wordcell"`, `workers_dev` true, `preview_urls` false, `assets` deep-equal `{ "directory": "./dist" }`; `compatibility_date` a `YYYY-MM-DD` string not later than the `DEFAULT_COMPAT_DATE` read from the pinned wrangler's `node_modules/wrangler/wrangler-dist/cli.js` (the test fails if the constant is not found; retro P3).
- Tests: `scripts/flaky-report.test.mjs`, `scripts/deploy-check.test.mjs`, `scripts/deploy-config.test.mjs` (Vitest include `scripts/**/*.test.mjs`), names starting `AD-18 …`. Network tests use an in-process `node:http` server on 127.0.0.1 port 0 with zero delay, no external network, inside the AD-17 unit budget (< 5 s). A unit test covers both protocol → module mappings; the real https path is first exercised at gate 4. Each script also gets one test that spawns its CLI with `node:child_process` against temp files (post-deploy also against the local server, via a base-URL override used only by tests), so the CLI wiring runs before gate 4 (retro P3). At least one flaky-report fixture is captured from a real `--reporter=json` run and includes nested describes.
- actionlint: a gating step in ci.yml's `test` job right after `checkout`: `docker run --rm -v "$PWD":/repo -w /repo rhysd/actionlint:1.7.12` (1.8's tag, 1.8 plan:84), no config or flags. CI-only like screenshots: `test:all` does not run it (Docker is not a unit-gate dependency); the second documented CI-only exception in AD-17 Scripts / AD-18 CI. The build runs the same command locally as its proof (Docker reachable 2026-09-28).
- Carried constraints: values reach scripts only through step `env:` or arguments (no `${{ }}` inside `run:` bodies); secrets stay only in the `deploy` step env; deploy.yml keeps `npm ci`, so scripts run after checkout.
- Doc updates, each tagged "(ticket 1.11, 2026-09-28)": spine AD-18 `Binds:` (`scripts/flaky-report.mjs`, `scripts/deploy-check.mjs` and the three test files), AD-18 CI (actionlint step, script steps) and AD-18 Deploy (immutable on JS, dictionary and woff2; extended verify dist; pre-deploy config test), AD-17 Scripts (actionlint CI-only); SPEC CAP-8 and CAP-9 success and D6 (actionlint now in CI); build-notes CAP-8 and CAP-9; delta-checks rows 48–49; epic Notes (the Docker "Unknown" is superseded). The AGENTS.md managed block is unchanged (actionlint is a lint step, not a suite; `test:all` still covers every suite except the screenshots).

## Acceptance Criteria

Verify: `npm run test:all` is green and the unit suite stays under 5 s; each of these fails a named `AD-18` test: `_headers` without the `/sw.js` rule, with a wrong immutable value, an extra rule, a duplicate rule or an unparseable line; `.assetsignore` without `.vite` or with an extra line; `wrangler.jsonc` with an extra key (e.g. `assets.not_found_handling`), a missing key, `preview_urls: true` or a `compatibility_date` later than `DEFAULT_COMPAT_DATE`; the flaky report lists a flaky entry in the summary and as a `::warning::` with `%` escaped, handles each outcome branch (skipped, failure without file, success without file → non-zero, unexpected outcome → non-zero), exits non-zero naming the step id on malformed JSON, valid JSON without `suites` and a spec without `tests`, still lists a flaky entry when that step failed, lists all three steps as "not run" when actionlint fails, and writes "No flaky tests." for zero flaky; the deploy check fails on a wrong or duplicated `cache-control` on the woff2 and on the dictionary, a redirect before 200 on a no-cache check (not followed), `/index.html` whose final response after a 307 lacks `no-cache`, a 200 where 404 is expected, an index body mismatch, a server that never responds (short test timeout) and a refused connection (each a failed attempt; the check fails once attempts run out), no workers.dev URL in the log, and verify dist with zero or two `en-*.txt`, zero or two `*.woff2`, a missing required file or zero `*.js`; each CLI spawn test passes; actionlint exits 0 locally and in CI. Gate 4: the owner pushes `epic-1-scaffold` (CI green including actionlint and the flaky-report summary), then the change reaches `main` and the Deploy run's post-deploy log shows every check ok, including the dictionary and woff2.
