# Controller seams

## Description

Behaviour-neutral split of src/ui/gestures/controller.ts along its seams before tile gestures land (retrospective A6, F14): the controller keeps the press machine; the visible band and clip move to gestures/visible-band.ts, the desktop hover-peek timer and suppress logic to gestures/hover-peek-timer.ts (src/ui/hover-peek.ts stays the render helpers; the cell-keyed timer, half-open suppress rects and their AD-12 Vitests kept, S17) and the fly-back to gestures/fly-back.ts, each behind the existing `deps` pattern (Seams); one gestures/lookup.ts helper taking the caller's message replaces every cell/column lookup with its own throw (Lookup), every throw string unchanged; gestures/classes.ts exports the class names the controller writes (Column.svelte and HoverPeek.svelte CSS keep literals, Classes); and the per-ticket "Entry N" header paragraphs in src/ui become one behaviour summary per module (Headers). controller.test.ts stays one file (epic 4 F41): every existing test, `vi.mock`/`vi.hoisted` block and the `setup()` harness stay in it, no new `vi.mock`; harness edits limited to import paths (the new modules import motion, prefs, game, overlays by the specifiers the harness handles: the first three mocked, overlays re-imported after `vi.resetModules()`). The only new test file is gestures/lookup.test.ts (Tests).

Line numbers: build-notes cite lookup lines, this ticket throw lines (controller.ts unchanged since f62a89a); re-grep before editing.

- Seams: only the visible band/clip, the desktop hover-peek timer and suppress, and the fly-back move; drag, `overSource` (Q-34, F37), tap actions, hover classes and the touch long-press peek (onTimer/peek release, line map 597–618) stay in controller.ts (tile.ts comes with CAP-4–6). Each module is a factory (like click-swallow.ts's `createClickSwallower`) or pure function that `createController` builds from the deps it already receives plus getter hooks for controller-kept state (`press`, `root`, `lastPoint`). visible-band.ts owns `clip`, `barRect` and `visibleBand` (with a `root()` getter). fly-back.ts owns `flying`, the `Flight` type, flyBack/settle/finishFlight and `translate()` (exported; dragMove imports it: one copy, no cycle), and exposes flyBack, finishFlight and `running()`; settle stays private; its factory takes `gate`, a `clearDrag(drag)` callback (`Drag` and `clearDrag` stay in controller.ts, which exports `type Drag`; fly-back.ts takes it by `import type` only) and `onSettle`. Construction: fly-back first with `onSettle: () => { hover.suppress(); refreshHover(); }` (resolved lazily), then hover-peek-timer with `flying: flight.running`, so settle keeps clearDrag → `gate.leave` → suppress → `refreshHover`. hover-peek-timer.ts takes getters `root()`, `lastPoint()`, `pressHeld()` (`press !== null`: any press, not refreshHover's crossed-press check), `flying()` plus the controller's deps, owns the cell-keyed timer and `suppressed`, and exposes hoverEnter, hoverLeave, stopHoverTimer, closeHover, hideHoverPeek, suppress and `reset()` (only nulls `suppressed`; detach calls it where it now writes `suppressed = null`); onHoverTimer, cellCards and helpers stay private. `attribute()` moves to lookup.ts. No new module imports controller.ts at runtime; no module-level state, so one `vi.resetModules()` per test still isolates them. Every call order is kept (`cancel` → `finishFlight`, `closeHover`, suppress; every statement order in pointerdown and detach); fly-back's two throws (`fly-back while one is running`, `fly-back animation cancelled`) move verbatim.
- Lookup: gestures/lookup.ts (build-notes tree), also imported by HoverPeek.svelte, WordCellView.svelte, tray/tags.ts: `found<T>(value: T | null | undefined, message: string): T`, the one helper (SPEC CAP-3), throwing `new Error(message)` verbatim only on `=== null || === undefined`, never other falsy values (CardId 0); `cellIn(cells: readonly CellView[], n: number, message)` matching the `cell` field (`find(c => c.cell === n)`), never by index; `columnIn(columns: readonly ColumnView[], n: number, message)` keeping today's index-plus-`column`-field check; both thin wrappers over `found` (view types by `import type` from src/engine/index.ts); other listed sites (DOM `closest`, registry finds) call `found` directly. Sites (authoritative): controller.ts 230, 241, 269, 470, 485, 557, 592, 847, 925; intent.ts 66, 104; HoverPeek.svelte 30; WordCellView.svelte 23; tray/tags.ts `originCard`, which keeps one message for both a missing and an empty cell. controller.ts 455, 461, 483, 537 and intent.ts 74 are not cell/column lookups and stay; every throw string unchanged (tests pin them with anchored regexes).
- Classes: the classes and custom properties the controller writes: classes.ts exports the nine class names (`wc-hover-tail`, `wc-grab`, `wc-drop`, `wc-drop-self`, `wc-drag-ghost`, `wc-drag-layer`, `wc-drag-target`, `wc-selection-suppressed`, `wc-hover-peek-hidden`), the `HOVER_CLASSES` tuple and the `HOVER_FROM`/`HOVER_LEN` custom-property names, every value byte-identical; every literal use in controller.ts and the new modules imports them; `lifted` stays a Card-owned literal. Column.svelte (`:global(...)` selectors, `var(--wc-hover-*)`) and HoverPeek.svelte (`:global(.wc-hover-peek-hidden)` only) cannot import TS: they keep their literals with one comment naming classes.ts. The plan notes this reading of SPEC CAP-3's "share".
- Headers: scope is every case-insensitive `entry \d+` (including "Epic 5 entry N") in comments of non-test src/ui files, Svelte `<style>` comments included (`grep -rniE 'entry [0-9]' src/ui --exclude='*.test.ts'`; at HEAD: gestures/controller.ts, gestures/intent.ts, App.svelte, Board.svelte, Card.svelte, Column.svelte, HoverPeek.svelte, WordCellView.svelte, hover-peek.ts, layout/layout.svelte.ts, layout/fit.ts, tray/tags.ts, tray/WordLine.svelte; re-grep). A header is the module's first comment block that is not a `biome-ignore` directive (in .svelte, inside `<script>`, wherever the imports sit); later blocks (e.g. App.svelte:32) are inline tags. A header with Entry paragraphs becomes one behaviour summary; a file with only inline tags gets only the tag rewrite. Each new module (visible-band, hover-peek-timer, fly-back, lookup, classes) gets a header summarising the behaviour it now owns; every rule id and accepted trade-off the old Entry paragraphs cite survives in some module's summary. Each tag becomes the ids from its entry's paragraph that cover the tagged sentence (e.g. controller.ts:207 Entry 13 → epic 4 SPEC F34, AD-12; AGENTS.md cite rules by id); if none covers it, the tag is dropped; a tag with no paragraph in its file (e.g. Card.svelte "Entry 7") takes those of that entry's paragraph in gestures/controller.ts's header (epic 4) or its epic 5 CAP (tickets.toml `covers`); where the sentence already cites ids, the tag is dropped. Every SPEC/build-notes CAP or F id in rewritten tags, headers and summaries carries its epic ("epic 4 SPEC F34", "epic 5 CAP-1"); AD-, R-, Q- ids stay unqualified; other inline comments (moved verbatim included) keep their ids unchanged. Forward references to unbuilt entries (tags.ts entry 4, Card.svelte "set by entry 5") are removed or replaced with their CAP id. Test files, src/shell and main.ts are out of scope.
- Interface: new gestures/visible-band.ts, hover-peek-timer.ts, fly-back.ts, lookup.ts, classes.ts; `createController(gate, deps)`, `ControllerDeps` and the returned `{ cancel, attach, refreshHover }` unchanged; main.ts untouched; App.svelte's wiring (controller creation, `attach`, the `refreshHover` reaction) unchanged, only its comments change (Headers).
- Tests: no test renamed, no assertion changed, no new rule coverage (build-notes CAP-3). One new file, gestures/lookup.test.ts (AD-12 test names, pure, no `vi.mock`, not rule coverage): null and undefined throw the caller's message verbatim, 0 is returned, `columnIn` throws on an index/`column`-field mismatch, `cellIn` finds a cell whose array index differs from its number. Other new modules get no test files. AD-17 unit median recorded before and after.
- Owns: the gestures/ split, lookup.ts and classes.ts every later gesture entry uses; S17.
- Consumers: the visible-band clip clips the rects of the drop targets registered in gestures/drop-target.ts before epic 4 `pickTarget`, and feeds Q-34 `hasLeftSource` and entry 7's tray-band target; the class names are used by Column.svelte and HoverPeek.svelte CSS and hard-coded in e2e/drag.spec.ts, tap.spec.ts, column-phases.spec.ts, wordcell-view.spec.ts, drag-interruptions.spec.ts, helpers.spec.ts and helpers/drag.ts (the `wc-drag-` prefix), and in controller.test.ts (classList order, e.g. `['wc-hover-tail', 'wc-grab']`); these literals stay unchanged; the plan's ticket review lists both.

## Acceptance Criteria

Verify: npm run test:all and npm run test:screens are green with no screenshot baseline change, every existing test passing with at most import and harness-path edits, and the plan recording the Linux-filesystem warm unit-suite median before and after the split. Median rule: each median is AD-17 Speed's method (one discarded warm-up, then the median of three `npm test` runs, `fsModuleCache` warm) on a Linux-filesystem checkout (e.g. ~/wordcell-watch); "before" at the epic branch HEAD at build start (hash recorded), "after" the finished build tree applied onto that hash (recorded as "build tree on <hash>"). The plan goes to `built` only if the after median is < 5 s and `setup()` still calls `vi.resetModules()` once; at ≥ 5 s, profile first (AD-17 Speed) before any test-file change (epic 4 F41); if before is already ≥ 5 s, record it and flag it for the owner instead. A rise over 10 % that survives one re-measure of both is recorded in the plan with controller.test.ts per-file timings and its cause and flagged in the plan's review for the owner, without blocking. The plan's sentence → test mapping is "none; behaviour-neutral (CAP-3)".
