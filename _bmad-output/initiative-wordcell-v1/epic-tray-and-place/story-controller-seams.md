# Controller seams

## Description

Behaviour-neutral split of src/ui/gestures/controller.ts along its seams before tile gestures land (retrospective A6, F14): the controller keeps the press machine; the visible band and clip move to gestures/visible-band.ts, the desktop hover-peek timer and suppress logic to gestures/hover-peek-timer.ts (src/ui/hover-peek.ts stays the render helpers; the cell-keyed timer and half-open suppress rects and their AD-12 Vitests kept, S17) and the fly-back to gestures/fly-back.ts, each behind the existing `deps` pattern (Seams below); one gestures/lookup.ts helper taking the caller's message replaces the listed cell/column lookups with their own throws (Lookup below) with every throw string unchanged; one gestures/classes.ts exports the class names controller.ts, Column.svelte and HoverPeek.svelte share (Classes below); and the per-ticket "Entry N" header paragraphs in controller.ts and the other src/ui files become one behaviour summary per module (Headers below); controller.test.ts stays one file (F41): every existing test, `vi.mock`/`vi.hoisted` block and the `setup()` harness stay in it, no new `vi.mock`; harness edits limited to import paths (the new modules import motion, prefs, game, overlays by the specifiers the harness already handles: the first three mocked, overlays the real module re-imported after `vi.resetModules()`); no new test files for the new modules.

Line numbers below are at HEAD; the build-notes line map is at f62a89a and has shifted by about one line, so the builder re-greps before editing.

- Seams: only the visible band/clip, the desktop hover-peek timer and suppress, and the fly-back move; drag, tap actions, hover classes and the touch long-press peek (onTimer/peek release, line map 597–618) stay in controller.ts (tile.ts comes with CAP-4–6). Each module is a factory (like click-swallow.ts's `createClickSwallower`) or pure function that `createController` builds internally from the deps it already receives plus getter hooks for the state the controller keeps (`press`, `root`, `lastPoint`); fly-back.ts owns `flying`, the `Flight` type and flyBack/settle/finishFlight and exposes `running()`; its factory takes `gate`, a `clearDrag(drag)` callback (`Drag` and `clearDrag` stay in controller.ts, which the press machine uses throughout; fly-back.ts takes `Drag` by `import type` only) and an `onSettle()` callback the controller wires as hover-peek-timer's suppress then `refreshHover`, so settle keeps clearDrag → `gate.leave` → suppress → `refreshHover`. hover-peek-timer.ts takes getter hooks `root()`, `lastPoint()`, `pressHeld()`, `flying()` (fly-back's `running`) plus the controller's deps, owns hoverEnter/hoverLeave/closeHover/hideHoverPeek/cellCards/suppress, the cell-keyed timer and `suppressed`, and exposes a `reset()` that detach calls where it now writes `suppressed = null`. The module-level `attribute()` helper moves to lookup.ts; `translate()` goes with its users. No new module imports controller.ts at runtime (no cycle); no module-level state, so one `vi.resetModules()` per test still isolates them. Every existing call order is kept (settle → `gate.leave`, suppress, `refreshHover`; `cancel` → `finishFlight`, `closeHover`, suppress; every statement order in pointerdown and detach unchanged); fly-back's two throws (`fly-back while one is running`, `fly-back animation cancelled`) move verbatim.
- Lookup: gestures/lookup.ts (build-notes tree), also imported by non-gesture files (HoverPeek.svelte, WordCellView.svelte, tray/tags.ts): `found<T>(value: T | null | undefined, message: string): T`, the one helper (SPEC CAP-3), throwing `new Error(message)` verbatim only on `=== null || === undefined`, never on other falsy values (CardId 0), plus `cellIn(cells, n, message)` and `columnIn(columns, n, message)` as thin wrappers over it (`columnIn` keeps today's index-plus-`column`-field check). Sites (authoritative; this replaces the lookups at these sites): controller.ts 230, 241, 470, 485, 557, 592, 847, 925; intent.ts 66, 104; HoverPeek.svelte 30; WordCellView.svelte 23; tray/tags.ts `originCard`, which keeps one message for both a missing and an empty cell. Every other throw stays as it is (e.g. controller.ts 269 `cell card outside [data-wordcell]`, 455, 461); every throw string unchanged (tests pin them with anchored regexes).
- Classes: the set is the classes and custom properties the controller writes: controller.ts and the new gestures modules import from classes.ts the nine class names (`wc-hover-tail`, `wc-grab`, `wc-drop`, `wc-drop-self`, `wc-drag-ghost`, `wc-drag-layer`, `wc-drag-target`, `wc-selection-suppressed`, `wc-hover-peek-hidden`) and the `HOVER_FROM`/`HOVER_LEN` custom-property names, every value byte-identical; the `lifted` class stays a Card-owned literal. Column.svelte and HoverPeek.svelte use the names in `<style>` `:global(...)` selectors and `var()` references, which cannot import TS: they keep their literals with one comment naming classes.ts.
- Headers: scope is every case-insensitive `entry \d+` (including "Epic 5 entry N") in comments of non-test src/ui files, Svelte `<style>` comments included (`grep -rniE 'entry [0-9]' src/ui --exclude='*.test.ts'`; at HEAD: gestures/controller.ts, gestures/intent.ts, App.svelte, Board.svelte, Card.svelte, Column.svelte, HoverPeek.svelte, WordCellView.svelte, hover-peek.ts, layout/layout.svelte.ts, layout/fit.ts, tray/tags.ts, tray/WordLine.svelte; re-grep). A file whose top-of-file header has Entry paragraphs gets one behaviour summary; a file with only inline or mid-file tags (e.g. App.svelte:32, layout.svelte.ts) gets only the tag rewrite, no new header. Each tag becomes the SPEC CAP/F/AD/R ids the same entry's paragraph cites (e.g. Entry 13 → F34, AD-12; AGENTS.md cite rules by id); where the sentence already cites ids, the tag is dropped. Every forward reference to an unbuilt entry (tags.ts entry 4, Card.svelte "set by entry 5") is removed or replaced with its CAP id. Test files, src/shell and main.ts are out of scope.
- Interface: new gestures/visible-band.ts, hover-peek-timer.ts, fly-back.ts, lookup.ts, classes.ts; `createController(gate, deps)`, `ControllerDeps` and the returned `{ cancel, attach, refreshHover }` unchanged; main.ts untouched; App.svelte's wiring (controller creation, `attach`, the `refreshHover` reaction) unchanged, only its comments change (Headers).
- Tests: no test renamed, no assertion changed, no new rule coverage (build-notes CAP-3); AD-17 unit median recorded before and after.
- Owns: the gestures/ split, lookup.ts and classes.ts every later gesture entry uses; S17.
- Consumers: the visible-band clip clips the rects of the drop targets registered in gestures/drop-target.ts before epic 4 `pickTarget`, and feeds Q-34 `hasLeftSource` and entry 7's tray-band target; the class names are used by Column.svelte and HoverPeek.svelte CSS and hard-coded in e2e/drag.spec.ts, tap.spec.ts, column-phases.spec.ts, wordcell-view.spec.ts, drag-interruptions.spec.ts, helpers.spec.ts and helpers/drag.ts (the `wc-drag-` prefix), and in controller.test.ts (classList order, e.g. `['wc-hover-tail', 'wc-grab']`); these literals stay unchanged; the plan's ticket review lists both.

## Acceptance Criteria

Verify: npm run test:all and npm run test:screens are green with no screenshot baseline change, every existing test passing with at most import and harness-path edits, and the plan recording the Linux-filesystem warm unit-suite median before and after the split. Median pass rule: each median is AD-17 Speed's method (one discarded warm-up, then the median of three `npm test` runs, `fsModuleCache` warm) on a Linux-filesystem checkout (e.g. ~/wordcell-watch), "before" at the epic branch HEAD at build start and "after" at the build's commit, both hashes recorded in the plan. Hard gate: after < 5 s and `vi.resetModules()` still once per setup. If after exceeds before by more than 10 %, re-measure both once; if it still does, the plan records per-file timings for controller.test.ts and the build fixes the cause (e.g. module state) before `built`. The plan's sentence → test mapping is "none; behaviour-neutral (CAP-3)".
