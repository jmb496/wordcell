# FLIP module and button-driven glides

## Description

Adds src/ui/flip.ts (F6): a `createFlip(deps)` factory (the gate; getters for the DOM root, since App mounts after main.ts builds the deps, for the reduced-motion flag, read at each play as fly-back.ts reads `prefs.motion.reduced` per flight, and for the resulting phase, main.ts passing `() => game.view?.phase` or equivalent; `duration()` from motion.ts) installed once from main.ts, after the gate and before `createController`, through a setter as act.ts's `setController` (`capture()`, `play()` or `finishAll()` before the install, or a second install, throws). The controller reaches flip only through `ControllerDeps` `finishGlides(): void` and `glidesRunning(): boolean` (main.ts passes `() => flip.finishAll()`; controller.test.ts fakes pass spies). `capture()` (a pending capture throws, rule 6) calls `finishAll()`, then `flushSync()` (so a selection act() or TopBar cleared just before is rendered and no lift is recorded), then records, keyed by `data-card-id` (AD-14 FLIP identity is the CardId; after a band change the live element is a new node), each live element's `.face` viewport rect and band, from its `data-place` (`column` → columns band, `tray`/`strip` → tray band, `cell` → WordCell band; any other value throws), and each band's `[data-band]` rect. `play(command, result)` consumes the pending capture (`play` without one throws, rule 6), calls `flushSync()` before measuring (the next rects include the re-layout and any scroll write), throws on a CardId present on only one side and starts every animation synchronously, so the animations exist when the click handler returns; it animates the faces after the move's update from previous to next rect, ease-out (as fly-back.ts), wrappers never transformed (a press mid-animation hit-tests the settled layout), every live card whose band-relative position changed animating (container or index, Flip, a k change with the block left; card ↔ compact tile by translate only, the face taking its new size at once and gliding from the previous rect's top-left), mirrors never in the glide, durations only from motion.ts, under reduced motion every animated face fading opacity 0 → 1 at its settled rect over 120 ms with no translate (as fly-back.ts). Each animation is gate-counted until its idempotent settle (as fly-back.ts `settle`): its `onfinish`, or `finishAll()`, which finishes every running animation and settles synchronously (one gate leave per counted animation, running set emptied), so a later `onfinish` is a no-op; a `cancel` event throws (rule 6). New game, Replay and restore never animate by construction: they go through the store, never capture/play, and act()'s `cancel()` finishes any running glide first. This ticket wires `finishGlides()` into the controller's `cancel()` beside `finishFlight()`, so act(), the hide flush and back settle any glide (F6), and into `pointerdown`, `glidesRunning()` joining `inFlight` beside `finishFlight()`/`parting.finishAll()` (AD-14: a press acts on, and measures, the settled faces); entry 16 keeps the release capture/play and the press-path P5.

The kind is a pure exported function of (command, DispatchResult, the resulting phase read after the flush), never from comparing views or a phase rule decided before dispatch (F7, AD-3). By command type: `undo` (with or without `unfinished`) and `redo` → `undoRedo`, except a committing `redo` (resulting phase `idle`, or `finished: 'won'`) → `flyToCell`; `confirm`, winning or not → `flyToCell`; `setTarget` and `giveUp` → empty animated set (`giveUp` has no caller until epic 6); every other command (drop, tapDestinationCard, setDestinationCount, flip, arrange, addFreeLetter, removeFreeLetter, validate, setPlacementOrder) → `snap` (F17; a release with an edit glides from its released point), a `validate` with `changed: false` with an empty animated set. A no-edit release dispatches nothing and never reaches `play`: it keeps fly-back.ts `flyBack` (CAP-5, CAP-6). For `flyToCell` `play` starts no animation and takes no gate count (the cards land at once, as today); entry 11 fills it in. A pure exported planner (per CardId the captured and next {band, viewport rect}, each band's rect before and after, kind and reduced flag → per-face keyframes) carries the frame rules: a same-band card inverts from the band-relative delta (a pure band shift gets none), a band changer from captured − next viewport rect, a change under 0.5 px on both axes is none (as the controller's `near()`). The Vitest (`environment: 'node'`, no DOM or WAAPI) drives it and the kind function with controller.test.ts-style fakes. The act()-wrapped callers (ActionBar, TopBar, ControlRow) call capture before and play after `game.dispatch` (Validate's existing `flushSync()` stays, F15/F21; entry 16 wires the controller's release callers); on Validate and on Undo to Composing the D faces glide from and to the column while their block copies appear or vanish at once (F22).

- Interface: New src/ui/flip.ts (`createFlip(deps)` and its install setter, `capture()`, `play(command, result)`, `finishAll()`, the pure kind function and planner); main.ts creates and installs flip; ActionBar, TopBar and ControlRow wrap dispatch in capture/play; `ControllerDeps` gains `finishGlides()` and `glidesRunning()`.
- Tests: R-70 Undo Place → Composing keeps the arrangement and Composing → Idle returns the cards, animated (P5 supp.); AD-14 F22 D faces from and to the column (P5); AD-14 one live element during a Validate glide, faces animate, wrappers and mirrors never (P5); AD-14 FLIP kinds, band-relative set, no motion on a pure band shift, durations, reduced-motion fade (S + P5); AD-14 finish-all path, `cancel()` and `pointerdown` (S).
- Owns: flip.ts, the kind table and the animated set; every later dispatching caller uses capture/play.
- Consumers: The gate's busy sources gain FLIP animations: list layout re-layout, the banner latch, w recompute and the controller's gate enter/leave; ActionBar/TopBar/ControlRow handlers change inside act(): list the AD-12 act() scan; the controller's `cancel()` and `pointerdown` gain `finishGlides()`: list act(), the before-hide flush, before-back, the press path and controller.test.ts's fakes.
