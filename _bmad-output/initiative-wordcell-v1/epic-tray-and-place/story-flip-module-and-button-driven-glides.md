# FLIP module and button-driven glides

## Description

Adds src/ui/flip.ts (F6): a `createFlip(deps)` factory (the gate; getters for the DOM root (App mounts after main.ts builds the deps), the reduced flag (`prefs.motion.reduced`, read at each play as fly-back.ts and motion.ts do) and the resulting phase (throws without a view); `duration` (motion.ts's, injected)) installed once from main.ts, after the gate and before `createController`, through a setter as act.ts's `setController` (`capture()`, `play()` or `finishAll()` before the install, a second install or a null root throws). The controller reaches flip only through `ControllerDeps` `finishGlides(): void` and `glidesRunning(): boolean` (main.ts passes `flip.finishAll` and `flip.running`; controller.test.ts fakes pass spies). `capture()` (a pending capture throws, rule 6) calls `finishAll()`, then `flushSync()` (so a selection act() or TopBar cleared just before is rendered and no lift is recorded), then records, keyed by `data-card-id` (AD-14 FLIP identity is the CardId; after a band change the live element is a new node), each live element's `.face` viewport rect and band, from its `data-place` (`column` → columns band, `tray`/`strip` → tray band, `cell` → WordCell band; any other value throws), and each band's `[data-band]` rect. `play(command, result)` consumes the pending capture (`play` without one throws, rule 6), calls `flushSync()` before measuring (the gate-deferred re-layout is entry 12's, CAP-9), throws on a CardId present on only one side and starts every animation synchronously; it animates the faces after the move's update from previous to next rect, ease-out, wrappers never transformed (a press mid-animation hit-tests the settled layout), every live card whose band-relative position changed animating (container or index, Flip, a k change with the block left; card ↔ compact tile by translate only, the face taking its new size at once and gliding from the previous rect's top-left), mirrors never in the glide, durations only from motion.ts, under reduced motion every animated face fading opacity 0 → 1 at its settled rect over `duration(kind)` (120 ms) with no translate (as fly-back.ts); while a band-changing glide (into or out of the tray) runs, the tile area takes `wc-drag-tiles` (F22/OQ-6) and each band-changing face a glide class (z-index 1, under the sticky bars' 2, no shadow; DESIGN.md layer order), both removed at the last settle (`finishAll()` included); same-band glides take neither. Each animation is gate-counted until its idempotent settle (as fly-back.ts `settle`): its `onfinish`, or `finishAll()`, which finishes every running animation and settles synchronously (one gate leave per counted animation, running set emptied), so a later `onfinish` is a no-op; a `cancel` event throws (rule 6). New game, Replay and restore go through the store, never capture/play (act()'s `cancel()` finishes any glide first). This ticket wires `finishGlides()` into the controller's `cancel()` beside `finishFlight()`, so act(), the hide flush and back settle any glide (F6), and into `pointerdown`, `glidesRunning()` joining `inFlight` beside `finishFlight()`/`parting.finishAll()` (AD-14: a press acts on, and measures, the settled faces).

The kind is a pure exported function of (command, DispatchResult, the resulting phase read after the flush), never from comparing views or a phase rule decided before dispatch (F7, AD-3). By command type: `undo` (with or without `unfinished`) and `redo` → `undoRedo`, except a committing `redo` (resulting phase `idle`) → `flyToCell`; `confirm`, winning or not → `flyToCell`; `setTarget` and `giveUp` → empty animated set; every other command → `snap` (F17; a release with an edit glides from its released point), a `validate` with `changed: false` with an empty animated set. A no-edit release dispatches nothing and never reaches `play`: it keeps fly-back.ts `flyBack` (CAP-5, CAP-6). For `flyToCell` `play` starts no animation and takes no gate count; entry 11 fills it in. A pure exported planner (per CardId the captured and next {band, viewport rect}, each band's rect before and after, kind and reduced flag → per-face keyframes) carries the frame rules: a same-band card inverts from the band-relative delta (a pure band shift gets none), a band changer from captured − next viewport rect, a change under 0.5 px on both axes is none. The Vitest (`environment: 'node'`, no DOM or WAAPI) drives the planner, the kind function and createFlip (fake root, faces with `animate()`). The act()-wrapped callers (ActionBar, TopBar, ControlRow) call capture just before and play after `game.dispatch` (Validate's existing `flushSync()` stays, F15/F21); on Validate and on Undo to Composing the D faces glide from and to the column while their block copies appear or vanish at once (F22).

- Interface: New src/ui/flip.ts (`createFlip(deps)` and its install setter, `capture()`, `play(command, result)`, `finishAll()`, `running()`, the pure kind function and planner); main.ts creates and installs flip; ActionBar, TopBar and ControlRow wrap dispatch in capture/play; `ControllerDeps` gains `finishGlides()` and `glidesRunning()`.
- Tests: R-70 Undo Place → Composing keeps the arrangement and Composing → Idle returns the cards, animated (P5 supp.); AD-14 F22 D faces from and to the column (P5); AD-14 one live element during a Validate glide, faces animate, wrappers and mirrors never (P5); AD-14 FLIP kinds, band-relative set, durations (S + P5); AD-14 no motion on a pure band shift, reduced-motion fade, finish-all path, `cancel()` and `pointerdown` (S).
- Owns: flip.ts, the kind table and the animated set; every later dispatching caller uses capture/play.
- Consumers: The gate's busy sources gain FLIP animations: list layout re-layout, the banner latch, w recompute and the controller's gate enter/leave; ActionBar/TopBar/ControlRow handlers change inside act(): list the AD-12 act() scan; the controller's `cancel()` and `pointerdown` gain `finishGlides()`: list act(), the before-hide flush, before-back, the epic 4 fly-back finish, the hover-peek timer and controller.test.ts's fakes.
