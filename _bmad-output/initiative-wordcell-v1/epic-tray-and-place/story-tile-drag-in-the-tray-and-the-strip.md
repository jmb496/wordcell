# Tile drag in the tray and the strip

## Description

Adds the tile drag to the controller (CAP-5) on entries 5 and 6: a tile press crossing 8 px clears the tile selection (F18) and drags the tile by `transform` on its face with no drag state in Svelte until release (the F18 threshold clear is the only selection write); the drag's `lift` is measured before the F18 clear (rest slot top minus face top: F2's 4 px if selected, else 0; not `SELECTION_LIFT_PX`, no new constant) so the face does not jump, and a fly-back lands it unlifted, restoring no selection; the tray band, clipped to the visible band (F4), is the single drop target accepted at ≥ 25 % of the dragged face's area; while accepted the other movable tiles part to the `insertionIndex` gap over `duration('parting')` (snap under reduced motion) by face transforms only, nothing drawn at the gap, and under 25 % every tile rests with the origin slot open; release over an accepted gap dispatches one `arrange` / `setPlacementOrder` iff the order changes by card, otherwise the tile flies back by the epic 4 `flyBack` with no edit (never a removal; the landing glide on an edit is entry 16's (CAP-8, F17)); a D-block mirror drag moves nothing and keeps a tile selection; `pointercancel`, `lostpointercapture` and `cancel({ byBack: true })` fly back (F5, F18); a back mid-drag leaves the app (bare-Board rule), and hide, or the `cancel()` that `act()` runs first, settles the drag at once (every face snaps to rest, no reorder dispatched, nothing selected, F18); `act()`'s own handler then runs as usual. Like the column drag, a tile drag clears the hover classes and closes the hover peek at its threshold and recomputes hover at its end or the fly-back's settle, superseding entry 5's crossed-tile-press tests and the controller header's "no tile drag until CAP-5".

- Drag layer: while a tile drag is active the controller puts a new `classes.ts` class, `wc-drag-` prefixed, on `.tiles` that lifts its overflow clip, and the dragged face takes `wc-drag-layer` with a TileRows-scoped rule matching Column's (z-index and shadow; above the bars and hover peek, below the scrim); `clearDrag` removes both (at the fly-back's settle, else at once); the origin slot shows nothing (no ghost).
- Drop target: `DropTargetParams` gains a `kind: 'tray'` variant registered on `[data-band="tray"]` (AD-12 `use:dropTarget`); a tray accessor (`columnTargets()` stays columns-only) reads the one registration (a second throws); its visible-band.ts-clipped rect is accepted at ≥ `MIN_RATIO`. The internal `Drag` gets a tile variant, flying back unless `reorder` changes the order; `flyBack`'s parameter may narrow to the fields it reads (no new export).
- Geometry (entry 6 owns it; nothing re-derived): at drag start measure `origin` once (per `slotRects`' JSDoc) and build `slots = slotRects(trayLayout(tileCount, w, trayInnerWidth), origin, tileCount)` (`w`, `trayInnerWidth` via a deps getter sharing Board's `metrics.board − 16`, never `window.innerWidth`; `tileCount` = every tray position: |M| + k Composing, n Place) and `gapRects(slots, perRow, tileCount, first, count)` over the movable run (Composing: `first` = k with the block on the left, else 0, `count` = |M|; Place: `first` 0, `count` n); each move calls `insertionIndex(dragged, gapRects)` and `partingOffsets(slots, tileCount, first, count, gap, from)` (`from` = the dragged tile's run index); release calls `reorder(order, from, gap)` and compares by card; D-block mirrors never move in a reorder.
- Parting: each gap or acceptance change animates every other movable face from its current transform to its new offset (rest included) over `duration('parting')`, the end transform written inline; under reduced motion every step snaps; on a no-edit release or any fly-back end the parted faces return to rest by their own WAAPI animation from their current transform over `duration('flyBack')` with the fly-back's reduced-motion treatment (`drag.faces` stays the dragged face); on an edit release, hide and `act()` every parting transform and animation clears at once; `pointerdown` and `cancel()` finish every running parting and return animation (as the fly-back). One gate count covers the parting set while any parting or return animation runs; a superseded face animation is read for its current transform, cancelled unsettled and replaced (AD-11, F6, F24).
- Release: it acts on the last pointermove's acceptance and gap, never recomputed at the pointerup point (as epic 4's column drop on the last-shown highlight); on an edit it finishes the parting, clears the drag and parting transforms in one `clearDrag` call (so entry 16 can call `flip.capture()` before it), then `gate.leave()`, then the dispatch; until entry 16 an edit renders the new order at rest at once with no glide.

Interface: Controller tile-drag path in gestures/tile.ts or the controller (tray-band drop target, parting WAAPI, release dispatch); no new exports beyond entries 5 and 6 except drop-target.ts's tray accessor (AD-12) and the drag-layer `classes.ts` class.
Tests: R-32 (UI) block drag moves nothing, gaps never inside or beyond the block (P5 part); R-32 drag past the block lands at the M end (P5 supp.); R-33 a dragged-out free letter is not removed (P5); R-34 drag-reorder (P5 supp.); R-51 strip drag reorder (P5 supp.); R-71 a no-change drag is not an edit, Redo stays enabled (P5 supp.); R-73 (UI) a reorder saved before the next action (P5 part); AD-12 tray band single target ≥ 25 %, clipped (P5); AD-12 F5 cancel paths: hidePage, back, pointercancel, act() mid-drag (S + P5); AD-12 F18 drag clears the tile selection (S); AD-10 parting 0.5 × base, snap under reduced motion (S).
Owns: The tile drag, the tray band as a drop target, the parting animation and the F5/F18 tile-drag ends.
Consumers (list in the ticket review): The visible-band clip (entry 4's visible-band.ts) now also feeds the tray band: epic 4 pickTarget/drop-target as its other consumers; gate enter/leave from the new drag: layout re-layout, the banner latch and w recompute.
