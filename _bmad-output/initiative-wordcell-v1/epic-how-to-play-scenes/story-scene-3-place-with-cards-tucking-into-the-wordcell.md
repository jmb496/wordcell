# Scene 3: place with cards tucking into the WordCell

## Description

Place scene laid out exactly like the game. The word's cards animate into the chosen WordCell leftmost first, each disappearing below the card above it, so the WordCell ends with one top card, not a stack; order dragging of tile D stays.

- Current state: scene id `place` was built in 8.3: `src/ui/scenes/place.ts`, `fixtures/how-to-play-place.json`. Layout is the 8.6/8.7 whole-play-area stage (`Scene.svelte` place mode); no new layout. Fixture commands, steps up to the Confirm tap (command 7) and frames 0 to 4 stay unchanged. Changed: the Confirm fly, which today slides the single `strip-4` block (the whole strip) to cell 6, and the final frame, which draws cell 6 as six cards (`cellCards`) and becomes one top card.
- Order dragging stays: tile D is dragged to the front (command 6; order D B A L K E, R-51); the free letter is L from cell 6 (R-41, R-60, Q-02).
- Tuck: the fly step stays step 6 (`place-step-6`; `rest` stays 6 x `flyToCell`). Step 6 drops `flies` and its whole `reveal` (today `{ show: 'place-5', hide: [], kind: 'overlay' }`, which `effects.ts` would turn into a phase-1 0-to-1 fade and dip E); it gains `Step.tucks` (`cell`, `letters` in placement order). `defineScene` throws (AGENTS rule 6) when `cell` is not the last `placeOrder` frame's `placeTarget` or `letters` differ from its `placeOrder`. In `effects.ts` the `fly` case handles `step.tucks` before the carry/layout check and ignores step 6's `times`. Each `tuck-k` (k 0 to 5, D B A L K E, R-51) lasts 6 multiples of `duration('flyToCell')` (Animation speed applies, HP-2): card k flies in slice k of six. Plumbing: `Effect` gains optional `easing` (default `'ease-in-out'`); `PlayerDeps.animate` in `player.ts` gains an `easing` argument, `ScenePlayer.play()` forwards `e.easing`, `animate` in `Scene.svelte` passes it, and the test fakes of `PlayerDeps` follow. `tuck-k` sets effect-level `'linear'` and keyframes `[{offset 0, start}, {offset k/6, start, easing 'ease-in-out'}, {offset (k+1)/6, end}, {offset 1, end}]`, omitting the one that would repeat offset 0 (k=0) or 1 (k=5) so the later keyframe at a shared offset carries the easing; card k-1 lands as card k starts.
- Flier geometry: each flier is a `Card place="tray" mirror="static" full` (as the strip tiles) (no `data-card-id`/`data-testid`, AD-14) in a `tuck-k` div at left 0, top 0, `transform-origin: 0 0`, with `--wc-w` `RICH_TILE_W` (36) and `--wc-slot` `RICH_SLOT` (40) as in `.tiles`, so it starts as the strip tile. The `tuck` layer sits (motion on only), in the frame of the `place-<i>` layers (top `TRAY_TOP`), transparent, DOM-after them, fliers in order D to E, so card k paints above card k-1 and `tuck` above `place-5`. Tile and column Card have the same height (`--wc-H`) and face margin (a new `FACE_MARGIN` 2 in `geometry.ts`) but faces 36 and 40 wide, so only x scales: sx = `CARD_W / RICH_TILE_W`, sy = 1. Start `translate(stripTileX(k)px, STRIP_TOPpx) scale(1, 1)`; end `translate((placeCellX(cell) + FACE_MARGIN - FACE_MARGIN * sx)px, PLACE_CELL_TOPpx) scale(sx, 1)` so each flier's face (the glyph differs by about 1 px at the swap, as font-size scales with `--wc-w`; accepted) covers cell 6's top-card face and the previous flier exactly. The build corrects the `MAX_CELL_CARDS` comment in `geometry.ts` (value stays 6).
- Effects and hand-off: new ids `tuck`, `tuck-0` to `tuck-5` and `confirm` (marked only on the `place-4` layer's Confirm span) join `placeScene.elements`. Phase 0: `tuck-0..5`; `tuck` (base opacity 0, opacity 1 for the six multiples); `strip-4` and `confirm` hide as constant-opacity `[{opacity 0}, {opacity 0}]` at the tuck start (the fliers coincide with the strip, so no tile shows twice); the ghost fades 1 to 0 as a phase-0 `times: 1` `flyToCell` effect (step 6 targets `confirm`, so otherwise it sits over empty space) and returns next loop because step 0 replays its 0-to-1 fade (`shown` logic in `effects.ts`). Phase 1 (`kind: 'overlay'`, times 1, fill forwards): the `step.tucks` expansion in `effects.ts` emits the swap itself, `place-5` `[{opacity 1}, {opacity 1}]` and `tuck` `[{opacity 0}, {opacity 0}]`, with `place-5` at base opacity 0 until then, so E never dips; the lit and target outlines of frame 4 pop off at the swap (frame 5 has none). Every `place-<i>` layer redraws cell 6 from the fixture start (L), so L stays under the fliers; there is no `cell6` element. All per-card state is WAAPI keyframes (no runtime inline style), so tap-restart, Replay, Previous and the loop restore frame 4's look (Pause freezes; it restores nothing). Hidden-page handling stays as in `player.ts` (checked at step boundaries) and a closed panel is the existing Carousel mechanism, unchanged and covered by existing tests.
- One card (epic decision 2026-10-17): the scene's drawing only; R-65 is untouched and the fixture `cells` entry (six cards) stays. A new boolean `Frame.cellTop` (set on the place scene's last frame only) makes `cellCards` in `Scene.svelte` return `[entry.cards.at(-1)]` for the stated entry's cell, so the final `place-5` layer renders exactly one Card (E) in cell 6, with motion on or reduced; the `tuck` layer is not rendered under reduced motion. Scoring and the other scenes keep full stacks. Reduced motion: Next shows the final frame (HP-1, HP-2); Confirm and the tuck share it as in 8.3.
- Start: the scene keeps its own fixture start (§8, set-up commands 0 to 2), no `opens`.
- Caption: unchanged, `text.howTo.scenes.place`, read from `text.ts` as the figure's `Scene.caption` (HP-6); rewording is the owner's.
- Boundary: the tuck is per card (a `QU` card is one card, R-65); only this six-card case.
