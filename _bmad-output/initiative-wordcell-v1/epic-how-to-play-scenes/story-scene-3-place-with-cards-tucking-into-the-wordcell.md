# Scene 3: place with cards tucking into the WordCell

## Description

Place scene laid out exactly like the game. The word's cards animate into the chosen WordCell leftmost first, each disappearing below the card above it, so the WordCell ends with a single top card and not a stack; order dragging of tile D stays as in the current scene.

- Current state: scene id `place` (position 3 in the carousel; an older comment in `e2e/how-to-play.spec.ts` says "scene 4 (place)") was built in 8.3: `src/ui/scenes/place.ts`, `fixtures/how-to-play-place.json`, `text.howTo.scenes.place`. Layout is already the whole-play-area stage and geometry of 8.6/8.7 (`Scene.svelte` place mode): columns, the tray strip, Confirm and WordCells 3 to 10 are drawn; no new geometry. Fixture commands, steps up to the Confirm tap (command 7) and frames 0 to 4 stay unchanged. Changed: the Confirm fly, which today slides the single `strip-4` block (the whole strip) to cell 6, and the final frame, which draws cell 6 as a stack of six cards (`cellCards`) and so becomes one top card.
- Order dragging stays: tile D is dragged to the front (`setPlacementOrder`, command 6; order D B A L K E, R-51: front = bottom); the free letter is L from cell 6, used and gone after Confirm (R-41, R-60, Q-02).
- Tuck (technical default; step ids stay): the fly step stays step 6 (`place-step-6`; `rest` stays 6 x `flyToCell`), so the e2e `lastStep` 6 is unchanged. Step 6 drops `flies` and its `reveal`; a new `Step.tucks` (`letters` in placement order, one start point per card, one end point, a scale) is expanded in `effects.ts` into the effects below. `defineScene` throws (AGENTS rule 6) when `letters` differ from the last `placeOrder` frame's or the end cell is not that frame's `placeTarget`. Each `tuck-k` (k 0 to 5, D B A L K E, R-51) lasts `times: 6` of `duration('flyToCell')` (no new FACTOR, so Animation speed applies, HP-2): six equal slices of the timeline, card k flying in slice k, so the tuck takes six multiples and nothing overlaps. `Effect` gains an optional `easing` (default `'ease-in-out'`; `animate` in `Scene.svelte` passes it); `tuck-k` sets `'linear'` and keyframes `[{offset 0, start}, {offset k/6, start, easing 'ease-in-out'}, {offset (k+1)/6, end}, {offset 1, end}]`. A card's start time is the offset of its last keyframe still at the start transform, k/6; the landing of card k-1 equals the start of card k. All end at the exact top-card box of cell 6, at the column Card's width and height (the same box as `place-5`'s E), so each covers the previous entirely. The fliers are `Card mirror="static"` (no `data-card-id`/`data-testid`, AD-14) in a `tuck` layer in `Scene.svelte` place mode (motion on only), DOM-after the `place-<i>` layers, in order D to E, so card k paints above card k-1 and `tuck` above `place-5`.
- Effects and hand-off: new ids `tuck`, `tuck-0` to `tuck-5` and `confirm` (marked only on the `place-4` layer's Confirm span) join `placeScene.elements` (the existing test requires every effect element in `elements`). Phase 0: `tuck-0..5`; `tuck` (base opacity 0, shown by an opacity 1 effect at offset 0 for the six multiples); `strip-4` and `confirm` opacity-only fades to 0 within the first multiple (no transform), while the fliers start at full opacity on the tile slots and tile size, so no tile shows twice; the ghost fades out over the first multiple (step 6 targets `confirm`, so otherwise it would sit over empty space), and the next loop's first step fades it in through the existing `shown` logic. Phase 1 (`kind: 'overlay'`, times 1): `place-5` set to opacity 1 and `tuck` to opacity 0 at the same instant (a swap, no overlap fade, so E never dips). Every `place-<i>` layer redraws cell 6 from the fixture start (L) and none is hidden, so L stays drawn under the fliers and D covers it entirely; there is no `cell6` element. All per-card state is WAAPI keyframes only (no runtime inline style), so Pause, tap-restart, Replay, Previous and the loop restore frame 4's look. Hidden-page handling stays as in `player.ts` (checked at step boundaries) and a closed panel is the existing Carousel mechanism, unchanged and covered by existing tests.
- One card: this is the scene's drawing only, per the epic decision of 2026-10-17; R-65 (all cards viewable) is untouched and the fixture `cells` entry (six cards) stays. A new `Frame.cellTop` (place scene's last frame only) makes `cellCards` in `Scene.svelte` return the last card of the stated entry, so the final `place-5` layer renders exactly one Card (E) in cell 6, with motion on or reduced; the `tuck` layer is not rendered under reduced motion. Scoring and the other scenes keep their full stacks. Reduced motion: Next shows the final frame (HP-1, HP-2). Confirm and the tuck share the final frame as in 8.3; there are no intermediate frames.
- Start: the scene keeps its own fixture start (the §8 position, set-up commands 0 to 2) and does not chain from scene 2's end state (no `opens`; the epic's "starts from" wording applies to scene 2 only).
- Caption: unchanged, `text.howTo.scenes.place`, read from `text.ts` as the figure's `Scene.caption` (HP-6); rewording is the owner's.
- Boundary: the tuck is per card (a `QU` card is one card, R-65); only this six-card case is in scope.
