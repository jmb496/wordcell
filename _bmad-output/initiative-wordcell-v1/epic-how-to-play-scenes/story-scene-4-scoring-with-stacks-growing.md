# Scene 4: scoring with stacks growing

## Description

Scoring scene starts as the game looks (WordCells recognisably on the board), animates each WordCell stack downwards to show how many cards it holds, then shows the per-cell numbers and the total; QU counts two.

- Current state: scene id `scoring` (8.3): `src/ui/scenes/scoring.ts`, `fixtures/how-to-play-scoring.json` (cells 3, 4, 6 = CAT, QUIT, BALKED: 3, 3, 6 cards). The shared `Stage.svelte` draws the stacks (`mini`) from the fixture start, today full from frame 0. No layout, `STAGE_H`, `opens` or fixture change; the `MAX_CELL_CARDS` comment stays. 8.8's `Frame.cellTop` is not used (full stacks at the end).
- Frame 0 look (glossary WordCell entry, R-65): cells 3, 4, 6 draw only their top card (T, T, E), as the game shows a WordCell; cells 5, 7 to 10 stay empty. R-52 applies only where the top card becomes the free letter, not here.
- Growth: new `Step.grows { cell, cards }` on the tap steps. Contract: `Stage.svelte` gains one optional prop `grow` (cell → card count), passed by `Scene.svelte` only with motion on and only for scenes with `grows` steps; other scenes are untouched. For such a cell each stack card is wrapped in a plain block div inside `.mini` carrying `data-scene-el="grow-<cell>-<j>"` (layout unchanged); j is the fixture list index (drawn order = list order, cell 6: D B A L K E): j = 0 first list card (highest on screen), j = n-1 top card drawn last and lowest; DOM order j ascending so later cards paint above. Stage computes the inline base style from `grow[cell]` and STRIP alone (a unit test pins it equal to the t=0 keyframes): j < n-1 opacity 0; the top card `translateY(-(n-1) * STRIP)` (the collapsed look); nothing else inline. Ids join `scoringScene.elements`.
- Order per cell (steps stay four taps; figure reveals 9, 16, 36, total 61): ghost taps the cell's top card (fixed point `stackPoint(cell, 1)`, replacing the height-dependent targets) and rests there while the stack grows beneath it; the stack grows; its figure fades in; step 3 (0-based, as in `scoring-step-<i>`) taps the total as today. With g = the step's `times` (`step.times ?? 1`, 2 here) and n the cards, the grow effects are phase 0 with `times` g + n - 1 multiples of `duration('flyToCell')` (no new kind; HP-2), effect easing `'linear'`, and hold for the first g/(g + n - 1) (the ghost's move). Slice m (0 to n-2) spans offsets o_m = (g + m)/(g + n - 1) to o_(m+1): the top card goes from `translateY(-(n-1-m) * STRIP)` to `-(n-2-m) * STRIP` with segment easing `'ease-in-out'`; card m appears (opacity 0 to 1, constant keyframes at o_m) hidden under the top card, so one card appears per slice and the top card ends at today's layout. n cards need n - 1 moves, so n - 1 slices, not n. The figure is the existing phase 1 reveal. Per step (multiples of `duration('flyToCell')`: wait + grow + figure, the figure being kind `overlay`, 0.5): 2+4+0.5, 1+4+0.5, 1+7+0.5, 1+2+0.5 = 24, plus rest 6 = 30 (today 15 + 6 = 21); at Slow (320 ms base, 640 ms a multiple) about 19 s, and step 3 starts about 13 s in, so the play-on-open poll timeout (30 s) still holds.
