# Celebration skip

## Description

Adds the skips on top of entry 5's trigger: a press outside the top bar, action bar and dictionary banner that began after the start (one-shot click swallow, consumed; a held finger and a banner button do not skip), `Space`/`Esc` on desktop (not while a bar or banner control has focus), and the Android back gesture through entry 4's `closedByBack` path; this entry owns the press-outside-the-bars e2e helper and adjusts the wave, stagger and physics constants and the copy scale that Jared's Android read calls for.

- Interface: capture-phase listeners owned by `celebration.svelte.ts`, `pressEscape`'s `celebration` branch, the `e2e/helpers/` press helper. Tests: R-87 skip rows (P6, `desktop` for the keys); UI Vitest `AD-19` listener tests (U: a press after vs before the start; a held pre-start pointer's release is not a skip while a new `pointerId`'s pointerdown skips; a press held over 300 ms before release; targets in a bar or the banner; keys with and without bar/banner focus; a repeat keydown and a Ctrl/Cmd/Alt chord do not call `end()`; a skip before the push settles; `end()` once; run listeners gone after end, back, cap and cancel; each tail gone after its release or expiry). Owns: the skips and the press helper. Consumers: entries 7 and 8 (entry 8 runs the press helper hook-free against `dist/`). Plan checkpoint: the build stops at its plan for the owner. Done checkpoint: gate 4 is Jared's Android read (Tuning; AC Device read).
- Press: the run's capture `pointerdown`/`pointerup`/`click`/`keydown` listeners attach at `start()` and detach at the internal stop every removal reaches (`ended` and `cancelled`; entry 4 Notes (d): teardown hangs there, not on `onEnd`). `end()` runs on the qualifying `pointerdown`: primary button only (`button === 0`), any pointer type, "after the start" judged per `pointerId` (a finger held from before the win stays inert even if a second finger lands); a target inside the top bar, the action bar or the dictionary banner passes through untouched (`act()` and its own path, AD-19 Skip). The skipping press leaves a one-shot tail for its `pointerId` that outlives the run: it consumes that pointer's `pointerup`, arms its own `createClickSwallower` there (`src/ui/gestures/click-swallow.ts`; the 300 ms counts from the release, as the controller does) and clears on `pointercancel`, so the release never collapses the just-opened sheet through its scrim or activates its first action. Only the skipping input is consumed: bar/banner presses and pointers held from before the start never are; a finish or the cap consumes nothing. A skip before the celebration's push settles calls `end()` at once; nav's pop-after-push queue orders the pop (AD-13). If the banner hides mid-run (Reload pressed) or appears mid-run, the band stays as measured at `start()`; presses on the banner always pass through; resize remains the only geometry end.
- Keys: the run's `keydown` listener (no platform gate; the key rows run on the `desktop` project) consumes `Space`/`Esc` and calls `end()` unless a top-bar, action-bar or banner control holds focus (AD-19 Skip); with such focus `Space` acts on the focused control natively. A repeat or a Ctrl/Cmd/Alt chord never skips; Shift+`Space` does not skip, Shift+`Esc` does (as `match` in `src/ui/keys.ts` handles them). It cancels the pointer controller first (`act()`/`cancelGesture()`, as `pressEscape` does). The skipping `Space` leaves a one-shot `keyup` tail that consumes the matching keyup and clears on it or on blur, so it cannot activate Replay this deal once the sheet takes focus. Esc today ends the run through `pressEscape` (`else overlays.close(top)`) whatever has focus; now the capture listener is the only Esc skip: `pressEscape` returns false (no `act()`, no `preventDefault`) while `celebration` is on top, so a bar- or banner-focused Esc reaches nothing (entry 4 Notes). `src/ui/keys.test.ts`'s entry-4 test "AD-13 Esc on the celebration closes it" is rewritten to that; the skip case moves to the AD-19 listener tests.
- Helper: `skipByPress(page)` in `e2e/helpers/celebration.ts`: DOM only (no `window.__wordcell`), waits for the mounted `[data-celebration-group]`s, presses a point inside the AD-12 visible band outside both bars and the banner (touch on touch projects, the mouse otherwise), returns once the expanded end sheet is visible; its own test in `e2e/helpers.spec.ts`.
- Tuning: the build ships entry 3's constants and copy scale unchanged and stops at the done checkpoint. Jared's values win (within F6/F7 and the AD-19 cap) and are applied on this ticket; if they move the last Slow launch before the Fast cap, the builder retargets entry 5's Slow-cap row (e.g. probe `running()` just after the last Slow launch) instead of changing the values. The AD-19 `step` tests and R-87 cap rows stay green; then `npm run test:all`, only the `e2e/celebration.screens.spec.ts` baseline regenerated in the container (`npm run test:screens -- e2e/celebration.screens.spec.ts --update-snapshots=changed`; the config only writes missing snapshots), no other baseline changed (`git status e2e/`), and `npm run test:screens` green; the owner's device read approves the new frame. The 50 % overlap and the 40 % floor are A-D12 / SPEC CAP-2 values, not tuning constants: a requested change to either is recorded for entry 9's doc sync as an owner amendment. The values and the A-D12 verdict go in the epic file's Notes for entry 9's doc sync. A copy cost that fails on the device stops for the owner (it reopens F2), never handled by the builder.

## Acceptance Criteria

Verify: `npm run test:all` and `npm run test:screens` are green, and the four R-87 skip rows of rule-coverage.md pass on `android` (`desktop` for `Space`/`Esc`); the R-87 interruption rows (hide/resize, keys while it runs, ☰, Undo/New game, Redo) stay with entry 7:

- Press outside the bars (consumed): the press ends the run and is held until the expanded sheet is visible, then released with the release point on the expanded sheet's scrim; one case presses a non-empty WordCell. For each, the sheet stays expanded, no WordCell view opened, the Session unchanged.
- `Space` and `Esc` (`desktop`): focus moves off every bar and banner control (e.g. focus the board) before the keyboard Confirm; then `Space` and, separately, `Esc` end the run; after the key's release the sheet is expanded, focus is on Replay this deal, the Session unchanged (Replay not activated by the keyup).
- Back: win → back → sheet expanded, app open; back again → sheet collapsed, app still open (no new code: entry 4/5's `closedByBack` path; this is the real-sheet proof entry 4 deferred here).
- Held finger and banner button: with focus moved off the bars before the keyboard Confirm, a touch held from before it (e.g. `e2e/helpers/touch.ts`) and released mid-run leaves `running()` true; a 500 dictionary route (as in `e2e/dictionary.spec.ts`'s Reload-after-500 case) shows the banner, and its `Reload` (by role and name) pressed mid-run leaves `running()` true and the sheet hidden.
- Screens: one `AD-17`-named frame in a new `e2e/celebration.screens.spec.ts`, `android` project only (`test.beforeEach(onAndroid)`, as `e2e/confirm.screens.spec.ts`) (won-words fixture, seam enabled, a fixed manual-clock advance mid-run, default theme), baseline generated in the container per AGENTS.md, regenerated after tuning per Tuning.
- Device read (done checkpoint): Jared's Android read of the first real win with the long-word fixture settles the copy cost (as the epic Notes say), the initial constants and A-D12 as far as the fixture shows them; what the fixture cannot show (A-D12's 40 % floor, a 23-letter row, hundreds of copies) is recorded in the epic Notes as carried to entry 9's final read, which needs a long-list fixture. Handoff (`unverified`, needs the device): `npm run build`, `npm run preview` (hook-free `dist/` on `localhost:4173`; a LAN `http://` origin is no secure context), chrome://inspect port forwarding `4173` → `localhost:4173`; on the phone, with no service worker controlling the origin (clear its site data: the precache's navigation fallback serves `index.html` to every navigation), open `localhost:4173/manifest.webmanifest`, write `fixtures/session-won-words.json` to `localStorage['wordcell:session']` from that tab's console (on the app page the AD-9 `pagehide` flush overwrites it), then open `/`, Undo, Confirm. Checklist: copy cost and frame rate, the constants' feel, A-D12 readability at the fixture's sizes, no trail and no colour change (rule-coverage Exempt), the press skip, back to skip then a second back collapsing the sheet.
