# Celebration skip

## Description

Adds the skips on top of entry 5's trigger (press, `Space`/`Esc`, Android back), the press helper, and the wave, stagger and physics constants and copy scale Jared's Android read calls for.

- Interface: capture-phase listeners owned by `celebration.svelte.ts`, `pressEscape`'s `celebration` branch, the `e2e/helpers/` press helper. Tests: R-87 skip rows (P6, `desktop` for the keys); UI Vitest `AD-19` listener tests (U: a press after vs before the start; a held pre-start pointer's release is not a skip while a new `pointerId`'s pointerdown skips; a press held over 300 ms before release; after a press skip the controller holds no press; targets in a bar or the banner; keys with and without bar/banner focus; a repeat keydown, Shift+`Space`, a Ctrl/Cmd/Alt chord and a non-primary button do not call `end()`, Shift+`Esc` does; a skip before the push settles; `end()` once; run listeners gone after end, back, cap and cancel; each tail consumes its release (`pointerup` and `click`; the Space repeats and `keyup`: stopped and default-prevented), then is gone; gone too on expiry or, for a press tail, the next `pointerdown`). Owns: the skips and the press helper. Consumers: entries 7 and 8 (entry 8 runs the press helper hook-free against `dist/`). Plan checkpoint: the build stops at its plan for the owner. Done checkpoint: gate 4 is Jared's Android read (Tuning; AC Device read).
- Press: the run's `document` capture `pointerdown` and `keydown` listeners (AD-19's `pointerup`/`click` consumption is the tail's) attach at `start()` and detach at the internal stop every removal reaches (`ended` and `cancelled`; entry 4 Notes (d): teardown hangs there, not on `onEnd`). `end()` runs on the qualifying `pointerdown`, stopped and default-prevented so the pointer controller (bubble phase) never opens a press for it: primary button only (`button === 0`), any pointer type, "after the start" judged per `pointerId`; a target inside the top bar, the action bar or the dictionary banner passes through untouched (`act()` and its own path, AD-19 Skip). The skipping press leaves a one-shot tail for its `pointerId` that outlives the run: it consumes that pointer's `pointerup`, arms its own `createClickSwallower` there (`src/ui/gestures/click-swallow.ts`; the 300 ms counts from the release, as the controller does) and, with that swallower, clears on `pointercancel` or the next `pointerdown` (as `disarm()` does), so the release never collapses the just-opened sheet through its scrim or activates its first action. Only the skipping input is consumed: bar/banner presses and pointers held from before the start never are; a finish or the cap consumes nothing. A skip before the celebration's push settles calls `end()` at once; nav's pop-after-push queue orders the pop (AD-13). If the banner hides mid-run (Reload pressed) or appears mid-run, the band stays as measured at `start()`; resize (entry 7) remains the only geometry end.
- Keys: the run's `keydown` listener (no platform gate) consumes `Space`/`Esc` and calls `end()` unless a top-bar, action-bar or banner control holds focus (AD-19 Skip); with such focus `Space` acts on the focused control natively. Repeats, chords and Shift as the U list (as `match` in `src/ui/keys.ts`). It calls `cancelGesture()` before `end()`. The skipping `Space` leaves a one-shot tail that consumes its repeats and matching `keyup` and clears on that keyup or window `blur`, so it cannot activate Replay this deal once the sheet takes focus. Esc no longer ends the run through `pressEscape` (`else overlays.close(top)`); the capture listener is the only Esc skip: `pressEscape` returns false (no `act()`, no `preventDefault`) while `celebration` is on top, so a bar- or banner-focused Esc reaches nothing (entry 4 Notes). The entry-4 tests "AD-13 Esc on the celebration closes it" (`src/ui/keys.test.ts`) and "AD-13 pressEscape with the entry on top: one pop, the callback gets ended, done once after a microtask" (`src/ui/celebration/attached.test.ts`) are rewritten to that; the skip case moves to the AD-19 listener tests.
- Helper: `skipByPress(page)` in `e2e/helpers/celebration.ts`: DOM only (no `window.__wordcell`), waits for the mounted `[data-celebration-group]`s, presses the centre of `[data-celebration-root]`'s rect (the band, AD-12; touch when `navigator.maxTouchPoints > 0`, the mouse otherwise), returns once the expanded end sheet is visible within 1 s of the press (well inside the run); its own test in `e2e/helpers.spec.ts`.
- Tuning: the build ships entry 3's constants and copy scale unchanged and stops at the done checkpoint. Jared's values win (within F6/F7 and the AD-19 cap) and are applied on this ticket; if they make the Slow run end before the Fast cap, the builder retargets entry 5's Slow-cap row (e.g. probe `running()` just before the Slow run ends) instead of changing the values. `step.test.ts`'s literal pins (e.g. the 0/160/320/480 ms launch offsets) take the new values; rule-coverage's AD-19 `step` behaviour rows and the R-87 cap rows stay green; a value breaking a behaviour row, like a copy cost failing on the device (it reopens F2), stops for the owner, never handled by the builder; then `npm run test:all`, only the `e2e/celebration.screens.spec.ts` baseline regenerated in the container (`npm run test:screens -- e2e/celebration.screens.spec.ts --update-snapshots=changed`; the config only writes missing snapshots), no other baseline changed (`git status e2e/`), and `npm run test:screens` green; the owner's device read approves the new frame. The 50 % overlap, 90 % fit share and 40 % floor are A-D12 / SPEC CAP-2 / DESIGN.md values, not tuning constants (a requested change is an owner amendment). The values, any amendment and the A-D12 verdict go in the epic file's Notes for entry 9's doc sync.

## Acceptance Criteria

Verify: `npm run test:all` and `npm run test:screens` are green, and the four R-87 skip rows of rule-coverage.md pass on `android` (`desktop` for `Space`/`Esc`); the R-87 interruption rows stay with entry 7:

- Press outside the bars (consumed): the press ends the run and is held until the expanded sheet is visible, then released with the release point on the expanded sheet's scrim; one case presses a non-empty WordCell. For each, the sheet stays expanded, no WordCell view opened, the Session unchanged.
- `Space` and `Esc` (`desktop`): the fixture route's Undo step leaves focus on the first strip card (`focusByPhase`), off the bars and banner, where `Enter` confirms (no focus move); then `Space` (held with `keyboard.down` until Replay this deal has focus, then released) and, separately, `Esc` end the run; after the key's release the sheet is expanded, focus is on Replay this deal, the Session unchanged (Replay not activated by the keyup).
- Back: win → back → sheet expanded, app open; back again → sheet collapsed, app still open (no new code: entry 4/5's `closedByBack`; the real-sheet proof entry 4 deferred).
- Held finger and banner button: with the `Enter` Confirm as above, a touch held inside the band, outside the bars and the banner, from before it (e.g. `e2e/helpers/touch.ts`) and released mid-run leaves `running()` true; a 500 dictionary route (as in `e2e/dictionary.spec.ts`'s Reload-after-500 case) shows the banner, and its `Reload` (by role and name) pressed mid-run refetches (a second route request) and leaves `running()` true and the sheet hidden.
- Screens: one `AD-17`-named frame in a new `e2e/celebration.screens.spec.ts`, `android` project only (`test.beforeEach(onAndroid)`, as `e2e/confirm.screens.spec.ts`) (won-words fixture, seam enabled, a fixed manual-clock advance mid-run, default theme), baseline generated in the container per AGENTS.md, regenerated after tuning per Tuning.
- Device read (done checkpoint): Jared's Android read of the first real win with the long-word fixture settles the copy cost (as the epic Notes say), the initial constants and A-D12 as far as the fixture shows them; what the fixture cannot show (A-D12's 40 % floor, a 23-letter row, hundreds of copies) is recorded in the epic Notes as carried to entry 9's final read, which needs a long-list fixture. Handoff (`unverified`, needs the device): `npm run build`, `npm run preview` (hook-free `dist/` on `localhost:4173`; a LAN `http://` origin is no secure context), chrome://inspect port forwarding `4173` → `localhost:4173`; on the phone, with no service worker controlling the origin (clear its site data: the precache's navigation fallback serves `index.html` to every navigation), open `localhost:4173/manifest.webmanifest`, write `fixtures/session-won-words.json` to `localStorage['wordcell:session']` from that tab's console (on the app page the AD-9 `pagehide` flush overwrites it), then open `/`, Undo, Confirm. Checklist: copy cost and frame rate, the constants' feel, A-D12 readability at the fixture's sizes, no trail and no colour change (rule-coverage Exempt), the press skip, back to skip then a second back collapsing the sheet.
