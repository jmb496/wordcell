# Celebration interruptions

## Description

Adds the new end paths on top of entries 5 and 6: the ☰ button and `M` (sheet expanded, then the menu after the push settles), the before-hide callback (sheet open queued for the next visible, idempotent) and `resize`/`orientationchange`; and proves with Playwright the behaviours entries 4 and 5 already provide: Undo, New game and the `N` key cancel without a sheet, a Redo that restores the win starts it again, and `?` and WordCell keys do nothing while it runs.

- Interface: `celebration.end()` as it is (no mode or parameter); `openMenu()` exported from `src/ui/open-surface.ts` for ☰ and `M` (no import cycle: celebration.svelte.ts's imports never reach open-surface.ts); a new UI module `src/ui/celebration/interruptions.ts` exporting `installInterruptions({ win, registerBeforeHide, halted, end })`, which registers the before-hide callback and the `win` `resize`/`orientationchange` listeners; `main.ts` calls it once at boot after its existing `registerBeforeHide` calls, passing `window`, `game.registerBeforeHide`, its `halted()` and `celebration.end`. Tests: R-87 interruption rows (P6, `desktop` for keys); UI Vitest `AD-19` hide, resize and menu wiring tests (AC). Owns: the menu, hide and resize ends of the run. Consumers: none. Plan checkpoint: the build stops at its plan for the owner's nod on the Hide rule 7 item below (story-celebration-overlay-entry-plan.md residual risks).
- Hide: the `installInterruptions` before-hide callback calls the ordinary `end()` (close → queued `nav.pop`), no mode flag or parameter. Idempotent: the second flush on `pagehide`, or no live run, is a no-op (`clear()` returns null). Entry 5's `done` closure already defers `openDeferred` to `game.whenVisible()` on a hidden page with no `announceOutcome()` (story-celebration-overlay-entry-plan.md owner item 1: no second `done` path). Rule 7 (plan checkpoint): this departs from AD-19 Hide's "the hide mode only stops the run and removes the entry"; the plan names that sentence and says why a queued pop is safe (nav.ts `pop()` has no timer; a `popstate` delayed while the page is frozen only delays the queued sheet push to the resume; `done` defers the open to `whenVisible()`). If the owner declines, the build stops for a ticket revision (a non-popping removal needs new AD-13 nav/overlays operations). If approved, entry 9 syncs AD-19 Hide (also: `installInterruptions`, not `main.ts`, registers the callback) and the EXPERIENCE.md Win celebration message row (it exempts only a sheet opened while hidden); the platform proof is entry 9's Android read. A `pagehide` while visible (reload, navigation away) also runs the hide end; a reload discards the page, so the visible branch's open and announce do not matter: "R-87 a reload mid-run is a relaunch: the sheet opens expanded at boot and no copy is drawn" (R-73) stays green as the proof.
- Resize: `installInterruptions` adds permanent `win` `resize` and `orientationchange` listeners that call `end()` (a no-op with no run; any such event during a run ends it, no size compare).
- Halted: the check `game.state.kind === 'halted'` (AD-15) lives in the hide and resize callbacks only (inside `installInterruptions`), never in `end()` (the cap and finish ends are unchanged): `game.svelte.ts` `flush()` runs them in every state, as `skip.ts` passes everything through while halted.
- Menu (SPEC F13, A-E16): `openMenu()` (Interface) is called by `src/ui/TopBar.svelte`'s `act(openMenu)` (its local `openMenu` goes) and the keys.ts `menu` row's `run`; `menu` joins `CELEBRATION_KEYS` (these change together: the keys.ts interim-gap comment, the overlays.svelte.ts `SUSPENDING` comment, the open-surface.ts header's "Synchronous … no second wait here" and Menu.svelte's "opened only through `openSurface('menu')` (the ☰ button)"). In keys.test.ts `menu` moves out of `KEY_OF` (no "AD-13 menu ("m") runs no attempt() row while only celebration is open" case); "AD-13 the KEY_OF table covers every ROWS id but undo and newGame" now excludes undo, newGame and menu (title to match); "AD-13 Z, Ctrl+Z and N act while only celebration is open" becomes "AD-13 Z, Ctrl+Z, N and M act while only celebration is open" (the `M` row runs `openMenu()`). With `celebration` open, `openMenu()` calls `celebration.end()`, then `nav.whenSettled(…)` runs `openSurface('menu')` (SPEC CAP-3, AD-19) only if the top entry is `endSheet`, else nothing (this ticket's default, for a SPEC F-row at entry 9's sync); otherwise today's `openSurface('menu')`. `act()` is unchanged (AD-19); the plan either wraps the deferred `openSurface('menu')` in `act()` or states why no gesture can start between the press and the settle. This closes entries 4–6's interim gap (☰ throws the `open(menu)` guard to AD-15; `M` is ignored).
- Keys (SPEC F15): `?` and WordCell `Enter` already do nothing (entry 4, `SUSPENDING`). For a WordCell tap, "does nothing" means no WordCell action: the tap is entry 6's consumed press skip, covered by "R-87 a touch press on a non-empty WordCell skips the run, consumed: …" (the `${name}` case of the press-skip test); entry 9 rewords the rule-coverage row, EXPERIENCE.md "Keys while it runs", AD-13's celebration sentence and SPEC F15 so each reads as no WordCell action (the press skips, R-87).
- Cancel: Undo (button, `android`; `Z`/Ctrl+Z, `desktop`), New game and `N` cancel (entries 4 and 5): `running()` false, no copies, no end sheet, no overlay history entry, and still no sheet after a few animation frames (`animationFrames`, e2e/helpers/lifecycle.ts); New game then back leaves the app (AD-13).
- Redo: the boundary case: Undo mid-run (no sheet), Redo → a new run, finish → exactly one expanded sheet.
